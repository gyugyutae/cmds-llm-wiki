# 항공우주 제조 AI 에이전트 아이디어 제안서

작성일: 2026-09-23
상태: 팀 논의용 초안 — 아래의 미결정 사항과 데이터 검증 결과에 따라 수정

## 1. 한 문장 제안

**프로펠러 시제품의 실제 추력·토크·소음 시험 데이터를 읽고, 서로 비교해도 되는 조건인지 먼저 검증한 다음, 목표 성능에 맞는 후보를 근거와 함께 선별하는 제조품질 검토 에이전트**를 만든다. 비교할 근거가 부족하면 억지로 1등을 고르지 않고 `선정 보류`와 그 이유를 제시한다.

가칭: **Propeller Evidence Agent**. 이름보다 중요한 것은 실측 파일을 새로 넣어도 같은 검토 절차가 재현된다는 점이다.

## 2. 왜 필요한가 — 제조를 모르는 팀원을 위한 설명

항공우주 부품은 단순히 “소음 수치가 가장 낮다”는 이유만으로 선택하기 어렵다. 프로펠러 형상에 따라 추력과 소음이 함께 달라지고, 같은 프로펠러라도 회전속도(RPM), 측정 위치, 시험 방식이 달라지면 수치를 그대로 비교할 수 없다. 품질담당자는 **어떤 부품을 어떤 조건에서 시험했으며, 해당 결론이 어느 측정값에서 나왔는지** 확인해야 한다.

우리의 첫 사용자는 양산품의 출하를 승인하는 사람이 아니라, **개발·시제품 단계에서 형상이 다른 프로펠러 후보의 시험 성적을 검토하는 제조품질 담당자**다. 이 사람이 풀 문제는 “목표 추력을 만족하면서 소음 측면에서도 검토할 가치가 있는 후보가 무엇인가?”이다. 에이전트는 최종 승인권자가 아니라 판단 근거를 정리하고 위험한 비교를 막는 보조자다.

## 3. 제품이 실제로 하는 일

1. 담당자가 목표 조건을 입력한다. 예: `최소 추력 40 N`, `가능하면 소음이 낮은 후보`, 필요시 토크·전력 제한.
2. 실측 파일을 업로드하거나 등록된 시험 기록을 선택한다. MVP에서는 공개 실험의 추력·토크 파일과 소음 스펙트럼 파일을 사용한다.
3. 에이전트가 파일과 시험 설명서에서 로터 형상, RPM, 추력, 토크, 마이크 위치, 소음 지표, 원본 출처를 찾는다.
4. Python 분석기가 단위·누락값을 검사하고, 목표 추력 충족 여부와 비교 가능한 시험 조건을 계산한다. **수치 계산과 적합성 규칙은 LLM의 추측에 맡기지 않는다.**
5. 에이전트가 결과를 확인해 `후보 선정`, `조건부 후보`, `선정 보류` 중 하나를 제안한다. 조건이 다른 데이터를 섞어 우열을 단정하지 않는다.
6. 원본 파일·측정 조건·판단 이유·한계를 연결한 분석보고서를 만든다. 품질담당자가 이를 검토해 최종 판단한다.

### 사용 장면 예시

담당자가 4엽과 5엽 프로펠러의 시험 파일을 넣고 “목표 추력 40 N 이상에서 더 조용한 후보를 골라줘”라고 요청한다. 에이전트는 먼저 추력 충족 여부를 살핀다. 이어 두 로터의 소음 시험 RPM과 마이크 위치를 확인한다. **현재 확보한 공개 데이터의 소음 측정은 4엽 8,900 RPM, 5엽 8,300 RPM으로 서로 다르다.** 따라서 이 자료만으로 동일 조건의 소음 우열을 확정할 수 없다는 점을 보여주고, 비교 가능한 추가 측정이 필요하다고 보고한다. 공개 데이터의 한계가 바로 우리가 막으려는 실무 오류의 사례다. [eVTOLUTION 데이터와 설명서][evto]

## 4. 여기서 ‘에이전트’는 무엇인가

일반적인 대시보드는 정해진 표와 그래프를 보여준다. 챗봇은 질문에 문장으로 답한다. **우리의 에이전트는 목표에 맞춰 필요한 자료와 분석 도구를 선택하고, 조건 충돌을 발견하면 추가 확인을 수행하며, 증거 수준에 따라 결론 자체를 바꾼다.**

| 구성요소 | 책임 |
|---|---|
| 데이터·DB | 시험 파일, 로터 형상·버전, 운전조건, 측정 위치, 출처를 연결해 보관 |
| Python 분석 도구 | 파일 파싱, 단위 확인, 성능 조건 필터링, 소음 지표 계산, 비교 가능성 규칙 적용 |
| AI 에이전트 | 어떤 도구가 필요한지 결정, 문서에서 조건·근거 탐색, 충돌 재확인, 결론과 한계 구성 |
| 품질담당자 | 에이전트의 근거를 검토하고 실제 후보 선정 여부를 최종 결정 |

핵심은 **“AI가 답을 잘 쓰는가”가 아니라 “언제 답하면 안 되는지 알고 필요한 검증을 실행하는가”**이다. 다중 에이전트 구성을 억지로 추가할 필요는 없다. 하나의 에이전트가 검증 가능한 여러 도구를 호출하는 편이 MVP에 적합하다.

## 5. 데이터 전략과 H200 활용

**1차 실측 데이터:** eVTOLUTION의 공개 실험 자료에는 형상이 다른 4엽·5엽 프로펠러의 RPM·추력·토크 텍스트 파일과 마이크별 소음 스펙트럼(HDF5), 시험 설명서가 있다. 파일 단위의 실제 업로드·분석을 입증하기 좋다. 다만 비교 가능한 소음 측정점이 얼마나 되는지 직접 확인해야 한다. [eVTOLUTION v1][evto]

**2차 참고 자료:** NASA의 소형 로터 시험 보고서는 여러 제작 방식, 형상 조건, 소음·공력 성능을 함께 다룬다. 본문·표·그림에서 값을 추출하면 반드시 원본 위치와 추출 방식을 표시하고 검수한다. 보고서에서 읽은 값과 원시 측정 파일을 동일한 증거 등급으로 취급하지 않는다. 소형 로터의 결과를 실물 UAM 기체의 성능으로 일반화하지 않는다. [NASA 보고서][nasa]

**새 파일 업로드:** 사용자가 같은 스키마의 새 시험 파일을 넣으면 자동으로 검토한다. 이것이 공개 데이터 전시와 실제로 쓰는 업무 도구를 가르는 기능이다. 단, 현장 데이터로 검증했다는 뜻은 아니다.

**H200이 제공될 경우:** 공개 시험 보고서의 표·그림·설명문에서 시험 조건과 근거 위치를 추출하는 문서·비전 모델, 또는 근거를 재확인하는 로컬 모델의 추론에 활용한다. 추출 결과는 규칙·원본 파일과 대조하고 의심 값은 사람이 검수한다. **H200은 보조 가속기이지 핵심 기능의 전제 조건이 아니다.** 팀별 접속 시점·할당량·사용 권한은 아직 확인되지 않았고, AWS 지원 역시 확인되지 않았다. 데이터 수가 적은 상태에서 “GPU로 소음 예측 모델을 학습한다”는 주장은 하지 않는다.

## 6. 우리의 차별성과 발표 강조점

- **실제 측정 데이터**를 사용하며, 새 시험 파일을 넣어도 분석이 다시 수행된다.
- 소음 최저값만 고르지 않고 **목표 추력과 시험 조건을 동시에 검사**한다.
- 비교가 불가능하면 **선정 보류**를 반환한다. 이는 실패가 아니라 품질 의사결정을 보호하는 기능이다.
- 결론에 원본 파일, 측정 지점, 조건, 계산 결과를 붙여 **다른 사람이 재검토할 수 있다.**
- AI의 자유로운 해석과 재현 가능한 수치 계산을 분리한다.

발표 데모는 두 장면을 목표로 한다. **정상 사례:** 조건이 맞는 파일을 넣어 후보와 근거가 제시된다. **함정 사례:** 조건이 다른 파일을 넣자 순위 산정을 보류하고 정확히 무엇이 부족한지 표시된다. 두 장면 모두 사전에 적어둔 답을 보여주는 것이 아니라 실제 업로드부터 보고서 생성까지 실행한다.

## 7. 제조 현장의 효용성과 타깃

첫 타깃은 항공우주·드론·eVTOL 관련 기업의 **개발품질/시험품질 담당자와 프로펠러 개발팀**이다. 특히 설계 수정이 잦고 시험 결과가 문서·스프레드시트·측정 파일에 흩어져 있는 시제품 단계에 맞는다.

기대 효용은 시험 자료 취합 시간 감소, 누락·단위 오류의 조기 발견, 부적절한 비교로 인한 후보 선정 위험 감소, 설계 변경 전후 근거 추적이다. 이것은 **검증할 가설**이며, 현재 효율 개선이나 불량 감소가 실측으로 입증된 것은 아니다. 항공우주 제조 AI에서 추적 가능한 판단의 중요성은 Airbus의 관련 연구 방향과도 맞닿아 있다. [Airbus TrustME][airbus]

## 8. 기대 비즈니스 가치와 최선의 확장 모습

사업화한다면 단순한 소음 DB가 아니라 **시험 데이터 검토 워크플로 제품**이 된다. 고객은 시험 파일 업로드, 설계 버전별 비교, 근거 보고서, 검토 이력을 한곳에서 관리할 수 있다. 가능한 과금 방식은 팀 단위 구독 또는 사내 설치형 라이선스이지만, 고객 인터뷰와 실제 데이터 연동 전에는 가격·매출을 추정하지 않는다.

가장 잘될 경우에는 프로펠러를 넘어 회전체·모터·팬 등으로 대상을 넓히고, 설계 정보와 실제 제작품, 시험 결과를 연결하는 품질 검토 플랫폼이 될 수 있다. **이는 장기 비전이지 이번 대회의 구현·검증 범위가 아니다.** 이번 대회 목표는 한 종류의 실측 데이터에서 후보 선별의 근거와 한계를 정확히 제시하는 작동하는 MVP다.

## 9. 현재 부족한 점과 위험

| 위험 | 대응 원칙 |
|---|---|
| 공개 데이터는 실제 제조 라인의 부품별 검사 데이터가 아니다 | “시제품 시험 결과 검토 도구”로 범위를 명확히 하고 현장 검증을 주장하지 않는다 |
| 4엽·5엽 소음 측정 RPM이 달라 직접 순위를 매기기 어렵다 | 비교 불가 판정을 핵심 기능으로 삼고, 별도의 비교 가능한 시험점을 확보했을 때만 조건부 순위를 제시한다 |
| 형상 차이 외에 운전조건·측정 위치가 결과에 영향을 준다 | 요인 설명은 가설로 표시하고 인과관계를 단정하지 않는다 |
| 소음 지표의 정의·주파수 범위·마이크 위치가 다르면 숫자 비교가 왜곡된다 | 지표 정의와 단위를 고정하고 원본 계산을 테스트한다 |
| 보고서 그래프를 AI가 잘못 읽을 수 있다 | 원본 위치 기록, 자동 대조, 사람이 확인한 값만 추천 계산에 사용한다 |
| GPU 접속이 늦거나 제한될 수 있다 | 핵심 분석은 Python만으로 동작하게 만들고 H200은 선택 기능으로 둔다 |
| 예시 업로드 파일이 실제 데이터처럼 보일 수 있다 | 실측 원본·변환본·데모 파일을 화면과 보고서에서 명확히 구분한다 |
| 현재 범위가 양산품 품질 보증이나 항공 인증을 충족하지 않는다 | 인증·실기체 성능 보장·현장 도입 완료 표현을 사용하지 않는다 |

## 10. 앞으로 할 일 — 결정과 검증의 순서

### 신청 계획서 작성 전(9월 23~27일 목표)

1. **문제와 사용자를 확정:** `시제품 단계 제조품질 담당자의 형상별 프로펠러 후보 검토`로 팀 합의.
2. **데이터 실사:** eVTOLUTION 원본 파일을 내려받아 Python으로 추력·토크 표와 HDF5 소음 스펙트럼을 읽고, 측정 조건을 확인한다. 데이터 라이선스·버전도 기록한다.
3. **판정 규칙 합의:** 목표 추력, 사용할 소음 지표와 주파수 대역, 마이크 위치, RPM 허용 차이, 결측 시 처리 방식을 정한다. 허용 차이는 임의로 정해 “동일 조건”이라고 주장하지 않는다.
4. **성공 기준 작성:** 새 파일 업로드가 되는지, 잘못된 비교를 막는지, 보고서의 모든 결론이 원본으로 거슬러 올라가는지 평가할 테스트 사례를 만든다.
5. **인프라 확인:** 주관 측에 H200 접속 시점·팀별 권한·사용 기간·원격접속 방식과 AWS 지원 여부를 문의한다. 확인 전 계획서에는 확정 자원으로 적지 않는다.

### MVP 개발 및 제출 준비(공개 안내상 9월 29일~10월 6일 대회 기간)

1. 파일 파서와 DB 스키마 구현: 로터 형상/버전, 시험조건, 추력·토크, 소음, 출처를 연결.
2. 수치 분석 및 비교 가능성 검사 구현; 정상·결측·조건 불일치 테스트 작성.
3. 에이전트가 DB 조회·분석 도구·근거 검사를 호출하고, 선정/조건부/보류를 결정하도록 연결.
4. 파일 업로드 → 결과 검토 → 근거 보고서까지 한 번에 보이는 간단한 화면 구현.
5. H200 사용권이 확인되면 문서·그래프 구조화 기능을 추가하되, 핵심 흐름이 먼저 완성되도록 한다.
6. 데모를 처음 보는 팀원에게 실행시켜 오해되는 표현, 실패하는 입력, 출처 누락을 고친다.

### 팀이 지금 결정해야 할 것

- 목표 조건을 `최소 추력 + 소음`으로 시작할지, 토크/전력 제한까지 MVP에 넣을지.
- 소음 지표를 무엇으로 통일할지. 원자료의 PSD에서 계산하는 방식과 측정 위치를 함께 정해야 한다.
- 실제 공개 데이터에서 **비교 가능한 정상 사례**가 확보되지 않을 경우, “후보 선정” 기능을 어디까지 주장할지.
- 누가 데이터 검증, Python/DB, 에이전트/화면, 발표·검증을 맡을지.

## 11. 제안서의 사실·가설 구분

**확인된 사실:** eVTOLUTION v1에 실측 추력·토크와 처리된 소음 스펙트럼 파일이 공개돼 있다. NASA에 관련 소형 로터 시험 보고서가 있다. 대회 주최 측은 세부 심사 배점표를 9월 29일 운영 설명회에서 공개할 예정이라고 안내했다. [eVTOLUTION][evto] · [NASA][nasa] · [주최 측 공지][contest]

**아직 검증할 가설:** 현장 품질담당자의 검토 시간이 줄어든다; 새 형상에도 같은 규칙이 유효하다; 고객이 실제 업무에 도입·지불할 의사가 있다; H200이 팀에 필요한 방식으로 제공된다.

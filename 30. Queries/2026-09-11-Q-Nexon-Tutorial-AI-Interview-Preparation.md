# 2026 넥토리얼 AI면접 준비 계획

## 결론

이번 AI면접은 2026년에 새로 도입된 전형이라 전년도 동일 전형 합격 후기는 없다. 공식 설명상 게임 프로그래머 기본기와 공통역량을 약 50분간 AI와 1:1 대화로 평가한다. 따라서 외운 1분 답변보다 제출 지원서의 각 문장을 연속 꼬리질문으로 방어하는 연습이 우선이다.

## 답변 기본형

`결론 한 문장 → 구체 사례 → 내 판단·기여 → 검증 결과 → 한계와 다음 행동`

- 모르면 아는 범위를 먼저 정의하고 모르는 경계를 말한다.
- AI가 작성한 코드를 본인 구현처럼 말하지 않는다.
- “AI를 썼다”에서 멈추지 않고 입력한 제약, 비교한 대안, 실행한 테스트, 발견한 오류를 설명한다.
- 수치나 결과는 증거가 있을 때만 말한다.

## 최우선 예상 질문군

1. 1분 자기소개와 왜 게임 프로그래머·넥슨인가.
2. 가장 자신 있는 프로젝트 하나의 문제, 구조, 본인 기여, 실패, 검증.
3. AI를 활용해 해결한 문제와 AI 답변이 틀렸던 사례.
4. AI 생성 코드를 어떻게 리뷰·테스트·수정했는가.
5. 협업 중 의견 충돌, 피드백 수용, 팀장으로 내린 결정.
6. C++ 또는 C# 경험과 메모리·객체 수명·값/참조 차이.
7. 배열·연결 리스트·스택·큐·해시·트리의 선택 기준과 시간복잡도.
8. 객체지향의 캡슐화·다형성·SOLID를 프로젝트 코드에 적용한 사례.
9. 프로세스와 스레드, race condition, lock/deadlock, 동시성 문제.
10. TCP/UDP, 연결 관리, 패킷 지연·유실을 게임 서버 관점에서 설명.
11. 좋아하는 게임의 재미 요소와 개선하고 싶은 시스템.
12. 모르는 기술을 빠르게 학습해 적용하고 검증한 경험.

## 사용자 기록에 맞춘 주의점

- 현재 주언어 기록은 Python이고 새 학습 방향은 Java다. 지원서 미리보기 텍스트만으로는 C/C++·C# 숙련도와 직접 구현 가능 영역에서 실제 선택한 항목을 식별할 수 없다. 선택값을 추측하지 말고 화면 원본으로 확인한다.
- `cuee`, `financial-order-latency-lab`, `Graduation-elasticsearch`의 코드는 AI 작성 비중이 크다는 기존 기록이 있다. 질문을 받으면 `문제 제시·설계 판단·AI 위임·직접 검증·미검증`을 분리한다.
- 가장 강한 공통역량 소재는 실리콘밸리 동아리 대표, 멋쟁이사자처럼 부대표, 팀장 경험이다. 그러나 “리더십이 좋다”가 아니라 결정·갈등·결과 한 사례로 답한다.
- 게임 경험과 C++/C# 직접 구현 증거는 현재 Wiki에 충분하지 않다. 지원서에 적은 게임과 기술을 기준으로 추가 답변을 만들어야 한다.

## 지원서에서 시작하는 공부 순서

지원동기와 게임 경험에 관한 개인화 답변은 [[2026-09-11-Q-Nexon-Tutorial-Motivation-and-Game-Answers]]에 별도로 정리했다.

### 1. 거래 안정성

지원 동기의 첫 문단이 가장 강한 기술 꼬리질문 출발점이다.

- 중복 요청: idempotency key, unique constraint, 중복 처리 결과 재사용.
- 연결 단절: 서버의 성공 여부와 클라이언트 응답 수신 여부는 다를 수 있음.
- 원자성: 재화 차감과 아이템 지급을 하나의 DB transaction으로 처리.
- 동시 구매: 동일 아이템에 대한 race condition, row lock 또는 optimistic locking.
- 취소·재시도: 상태 전이와 audit log, exactly-once를 쉽게 약속하지 않는 이유.
- 연습 문제: “동일 아이템을 두 명이 동시에 구매하면?”과 “결제 성공 직후 응답이 끊기면?”을 각각 90초로 설명.

### 2. 제출한 프로젝트 방어

Threads를 대표 프로젝트로 정했다면 다음을 코드·로그 없이도 설명할 수 있어야 한다.

- 자동화 파이프라인의 실제 단계와 각 단계의 입력·출력.
- API 실패 종류, 재시도 여부, JSON 오류 처리, provider fallback의 의미.
- 29개 테스트가 검증한 것과 검증하지 않은 것.
- 2 → 63, 28/32, 650의 측정일·원본·대표 게시물 선정 기준.
- 포맷 변경 외 다른 요인이 반응 증가에 영향을 줬을 가능성.
- 전체 자동 게시 장애가 아직 해결되지 않은 정확한 상태.

### 3. C/C++와 PX4 주장 방어

- pointer와 reference, stack과 heap, struct/class, const, compile/link의 기본 차이.
- PX4에서 실제로 열어 본 파일·함수, 바꾼 줄, 빌드·시뮬레이션 명령, 결과를 설명.
- MAVLink가 무엇을 운반하고 Pixhawk와 PX4의 역할이 어떻게 다른지 설명.
- 실제 기체 시험은 하지 않았다는 한계를 그대로 유지.
- 코드 위치나 변경 내용을 기억하지 못하면 “탐색·수정 경험”의 범위를 낮춰 정직하게 답변.

### 4. 자료구조·알고리즘

- array/list, stack/queue, hash table, tree와 시간복잡도.
- BFS/DFS 선택 기준과 visited 관리.
- 자물쇠와 열쇠: 열쇠 회전, 보드 확장, 경계 처리, 시간복잡도를 종이에 설명.
- 통과 코드를 외우는 대신 입력·출력·제약과 실패했던 경계 조건을 설명.

### 5. 공통역량

- CUEE 방향 전환에서 최초 의견, 반대 의견, 팀원 기여, 본인 결정, 결과를 분리.
- 수상 결과가 제품 시장성이나 실제 사용자 검증을 자동으로 증명하지 않는다고 설명.
- LLM Wiki는 도구 이름보다 실제로 모호한 문서를 어떻게 수정했고 다음 세션 결과가 어떻게 달라졌는지 한 사례를 준비.

## 하루 압축 계획

1. **90분 — 지원서 주장 감사**: 네 문항에서 명사·숫자·기술을 표시하고 각각 꼬리질문 3개 작성.
2. **90분 — 거래 시스템 기초**: transaction, idempotency, 동시성, 상태 전이를 말로 설명.
3. **60분 — Threads 방어**: 구조·실패·29개 테스트·지표 한계를 2분 답변으로 녹화.
4. **60분 — C/C++·PX4 방어**: 실제 한 일과 기억나지 않는 일을 분리한 뒤 기본 개념 복습.
5. **45분 — 자료구조**: 자물쇠와 열쇠 풀이와 대표 자료구조 선택 이유 설명.
6. **45분 — 모의면접**: 12개 질문을 답하고 매 답변 뒤 “왜?”, “어떻게 검증했나?”, “본인이 직접 한 것은?”을 추가.
7. **20분 — 장비 점검**: 실제 응시 링크에서 5초 녹화 완료.

새로운 내용을 넓게 암기하기보다 제출한 주장에 대한 방어력을 먼저 높인다.

## 과거 합격자·지원자 후기에서 가져올 것

- 2021년 최종합격자는 CS와 알고리즘을 꾸준히 준비했고, 실제 면접에서 DB 정규화 등 기초를 깊게 확인받았다고 회고했다.
- 2023년 지원자는 포트폴리오와 과제, 플레이한 게임을 꼼꼼히 질문받았고 즉흥 꼬리질문의 리듬이 빨랐다고 기록했다.
- 공통 교훈은 `지원서·프로젝트를 정확히 알고, CS 기본기를 말로 연결하며, 게임에 대한 자기 관점을 준비하라`는 것이다.
- 단, 이 후기는 과거 사람 면접/직무과제 후기이며 2026 AI면접 문항의 직접 근거가 아니다.

## 응시 전 실행 체크리스트

### 전날

- 개별 링크의 사전 점검 페이지에서 5초 녹화까지 완료한다.
- 실제 응시할 Chrome/Edge 최신 버전, 카메라·유선 마이크·스피커, 전원, 네트워크를 검사한다.
- 지원서와 포트폴리오를 다시 읽되, 응시 중 참고하지 않는다.
- 위 12개 질문을 60초·120초 두 버전으로 소리 내어 녹화한다.

### 당일

- 14:20까지 알림·메신저·화상회의 앱과 불필요한 탭을 종료한다.
- 14:30 정시에 대기실에 입장하고 14:40 전에 면접 시작 버튼을 누른다.
- 전문용어와 영문 약어를 또박또박 말하고 답변 종료 버튼을 확인한다.
- 전체화면을 유지하며 메모·휴대폰·두 번째 모니터를 참고하지 않는다.

## 남은 개인화 입력

제출한 지원서·포트폴리오 사본을 확보하면 문장별 예상 꼬리질문과 답변을 추가한다. 특히 지원 동기, C++/C# 경험, 좋아하는 넥슨 게임, 대표 프로젝트를 먼저 대조한다.

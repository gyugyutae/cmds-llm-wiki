# AI 시대 개발자 취업 공부 우선순위

## 결론

김규태가 좋은 금융권·핀테크 개발 직무에 취업하려면 지금 가장 먼저 채워야 할 것은 자격증 개수나 AI 도구 숙련도가 아니다. 현재 가장 큰 병목은 **Java와 SQL로 기능을 직접 구현하고, 오류를 추적해 수정하며, 테스트와 수치로 검증했다는 증거가 부족한 것**이다.

따라서 준비의 중심은 다음 한 문장으로 고정한다.

> Java·Spring·DB 기본기를 이용해 금융 거래의 정확성과 장애 조건을 구현하고, AI가 만든 결과까지 직접 설명·수정·검증할 수 있는 백엔드 개발자

## 준비해야 할 역량의 우선순위

| 우선순위 | 역량 | 공부할 내용 | 취업 증거 |
|---:|---|---|---|
| 1 | Java 구현력 | OOP, 컬렉션, 예외, 불변 객체, 제네릭, 동시성 기초 | 주문·계좌 도메인 코드, JUnit, 직접 수정 기록 |
| 2 | SQL·DB | JOIN, 집계, 서브쿼리, 윈도 함수, 모델링, PK·FK·UNIQUE, 인덱스, 트랜잭션 | SQL 풀이 로그, ERD, `EXPLAIN`, 정합성 테스트 |
| 3 | Spring 백엔드 | HTTP, MVC, DI, 요청 검증, JPA, `@Transactional`, 예외 처리 | 실행 가능한 REST API와 통합 테스트 |
| 4 | 문제 해결·코딩테스트 | 배열·문자열·해시, 스택·큐, 정렬, 이분탐색, DFS·BFS, 그리디, 기초 DP | Java 풀이와 복잡도·오답 설명 |
| 5 | 금융 시스템 | 주문·이체 상태, 원장, 멱등성, 대사, 감사 로그, 부분 실패 | 중복·동시성·복구 시나리오 |
| 6 | 운영·성능 | Linux, 로그, Docker, CI, 모니터링, 부하 테스트, p95·p99 | 재현 명령과 before/after 수치 |
| 7 | 설명·협업 | Git, issue, PR, ADR, README, 기술 발표 | 2분·15분 프로젝트 설명, 리뷰 가능한 이력 |
| 8 | AI 협업 | 초안, 반례, 테스트 보조, diff 검토, 검증 | `AI gave / I decided / I verified / Unknown` 기록 |

2026년 하반기 우리은행 TECH 전형도 알고리즘과 SQL 코딩테스트, 포트폴리오를 포함한 면접을 함께 제시한다. 이는 알고리즘만 풀거나 프로젝트만 만드는 한쪽 준비보다 Java·SQL·포트폴리오를 동시에 유지해야 한다는 최신 근거다.

## 가장 먼저 할 일

### 1. 첫 2주: 현재 실력을 측정한다

- Java로 클래스·enum·컬렉션·예외를 사용한 작은 주문 프로그램을 만든다.
- AI 도움 없이 프로그래머스 2단계 Java 문제 3개를 제한 시간 안에 푼다.
- SQL `JOIN`·집계 문제를 각각 2개씩 직접 푼다.
- 결과를 `혼자 해결 / 힌트 후 해결 / 코드 생성 필요 / 설명 불가`로 분류한다.
- 목표 회사 20곳의 언어, SQL 시험, 졸업요건, 포트폴리오 요구를 표로 만든다.

진단의 목적은 점수를 자책하는 것이 아니라 앞으로 8주의 시간을 어디에 배분할지 결정하는 것이다.

### 2. 첫 8주: 작은 금융 백엔드 MVP를 만든다

프로젝트는 국내주식 주문 또는 계좌이체 중 하나만 고른다. 취업 서사와 기존 관심을 고려하면 국내주식 현물 주문을 기본안으로 둔다.

1. `Order`, `Account`, `Execution` 도메인과 상태 전이를 구현한다.
2. 잔액 부족, 잘못된 상태 전이, 중복 주문을 테스트한다.
3. 계좌·주문·체결 ERD와 SQL을 직접 작성한다.
4. Spring Boot REST API로 주문 생성·조회·취소를 연결한다.
5. DB 트랜잭션 실패와 동시 요청 문제를 재현한다.
6. 멱등성 키와 잠금 전략을 적용하고 선택 이유를 기록한다.
7. Docker와 CI로 다른 사람이 실행할 수 있게 만든다.
8. README에 실패 사례, 수정 과정, AI 기여 경계를 남긴다.

초기에는 Kafka, Redis, Kubernetes, MSA를 넣지 않는다. DB 트랜잭션만으로 해결되지 않는 문제가 실제로 재현될 때 도입 여부를 판단한다.

### 3. 2026년 12월까지: 지원 가능한 v1을 만든다

- 핵심 API가 실행된다.
- 정상·경계·실패·통합 테스트가 있다.
- 프로젝트 전체 코드 흐름을 직접 설명하고 작은 요구 변경을 처리할 수 있다.
- ERD와 트랜잭션 경계를 설명할 수 있다.
- 중복 요청이 한 번만 처리됨을 테스트로 보여준다.
- README와 CI가 있으며 재현 명령이 한 줄로 정리돼 있다.

### 4. 2027년 1~2월: 좋은 회사가 파고들 만한 깊이를 만든다

- 동시에 여러 주문이 들어오는 race condition을 재현한다.
- 낙관적 잠금과 비관적 잠금을 비교한다.
- 서버 중단 또는 DB 지연 후 복구 절차를 만든다.
- 일별 대사로 원장과 잔액 불일치를 탐지한다.
- 부하 테스트에서 처리량, 오류율, p50·p95·p99를 측정한다.
- 병목 하나를 찾아 before/after 수치로 개선한다.
- 1페이지 이력서와 2분·15분 프로젝트 설명을 완성한다.

## 주간 운영안

18학점 학기에는 주 12시간을 끊기지 않는 최소선으로 두고, 가능한 주에는 16~20시간까지 늘린다.

| 영역 | 최소 시간 | 주간 완료 기준 |
|---|---:|---|
| Java·Spring·프로젝트 | 6시간 | 동작하는 작은 기능 또는 실패 테스트 1개 |
| 알고리즘 | 3시간 | Java 3문제와 오답 1개 설명 |
| SQL·DB | 2시간 | SQL 2~4문제와 프로젝트 쿼리 1개 |
| README·공고·회고 | 1시간 | 기록 1회와 공고 자격 확인 |

공부 시간은 강의를 재생한 시간이 아니라 직접 작성·실행·설명한 결과로 계산한다. 시험기간에는 Java 문제 2개와 프로젝트 커밋 1회를 최소 루틴으로 유지한다.

## AI를 사용하는 학습 규칙

AI 사용 자체를 제한하지 않는다. 다만 기능 하나마다 다음 과정을 지킨다.

```text
요구사항·불변조건을 직접 작성
→ 먼저 구현하거나 의사코드 작성
→ AI로 힌트·대안·반례를 탐색
→ 생성된 diff를 한 줄씩 검토
→ 정상·경계·실패 테스트 실행
→ 작은 요구 변경을 직접 수행
→ 판단과 검증 결과 기록
```

AI에게 완성 코드를 받았는데 설명하거나 수정할 수 없다면 그 기능은 완료된 포트폴리오 증거로 계산하지 않는다. 반대로 AI가 코드를 생성했더라도 문제와 제약을 직접 정의하고, 동작 원리를 설명하고, 실패를 찾아 수정하고, 테스트로 검증했다면 AI 시대의 유효한 엔지니어링 증거가 된다.

## 자격증과 영어의 위치

- 토익스피킹과 SQLD는 정해진 기간 안에 짧게 마무리한다.
- 정보처리기사는 금융권·공공 성격 회사의 서류 보완용으로 준비한다.
- 자격증 때문에 프로젝트와 Java 코딩테스트 루틴을 중단하지 않는다.
- 추가 자격증은 목표 공고에서 실제 가점을 확인하기 전까지 늘리지 않는다.
- 영어는 점수와 별개로 영어 기술 문서 읽기, README 한 단락, 프로젝트 2분 설명으로 연결한다.

## 좋은 곳에 갈 가능성을 높이는 지원 전략

좋은 곳을 대형 은행과 최상위 핀테크로만 정의하면 첫 취업 확률이 낮아진다. 지원은 세 층으로 운영한다.

| 층 | 지원 대상 |
|---|---|
| 상향 | 시중은행, 인터넷은행, 대형 핀테크, 대형 증권사 |
| 적정 | 카드·보험·증권 IT, 금융 IT 자회사, PG·결제사 |
| 진입 | 금융 솔루션사, 금융 SI, 중소 핀테크, 개발 인턴 |

2027년 2월까지 지원 가능한 상태를 만들고 3월부터 지원과 프로젝트 개선을 병행한다. 40~50개 회사를 조사하고 최소 30개에 지원하며, 서류·코딩테스트·면접 탈락 원인을 각각 기록한다.

## 하지 말아야 할 우회

- 자격증을 모두 딴 뒤 프로젝트를 시작하기
- Java 기본서를 완독한 뒤 코드를 작성하기
- 강의 프로젝트를 그대로 복제하기
- 기술 이름을 늘리기 위해 MSA·Kafka·Kubernetes를 먼저 넣기
- AI 생성 코드의 양을 성과로 말하기
- 상위 금융사 몇 곳만 지원하고 결과를 기다리기
- 프로젝트가 완벽해질 때까지 지원을 미루기

## 2027년 2월 완료 기준

- [ ] Java 문제를 제한 시간 안에 풀고 복잡도를 설명한다.
- [ ] `JOIN`, 집계, 서브쿼리, 윈도 함수를 직접 작성한다.
- [ ] Spring 요청 흐름과 `@Transactional`의 프록시 동작을 설명한다.
- [ ] 프로젝트 쿼리의 인덱스와 실행계획을 설명한다.
- [ ] 동시 주문 문제를 재현하고 잠금 선택을 설명한다.
- [ ] 중복 주문이 발생하지 않음을 테스트한다.
- [ ] 장애 또는 성능 개선 사례가 최소 하나 있다.
- [ ] 프로젝트 전체를 실행·설명·수정할 수 있다.
- [ ] AI의 기여와 본인의 판단·검증 범위를 공개할 수 있다.
- [ ] 프로젝트를 2분과 15분 버전으로 발표할 수 있다.
- [ ] 1페이지 이력서와 회사별 수정본이 있다.
- [ ] 모의 기술면접을 최소 3회 완료했다.

## 현재 품질 공백

- Java 직접 구현 수준을 보여주는 진단 결과가 없다.
- 새 금융 프로젝트 저장소와 최종 범위가 아직 확인되지 않았다.
- SQL 풀이와 코딩테스트 오답 로그가 없다.
- 기존 프로젝트는 AI 작성 범위가 커서 직접 구현·수정·검증 증거가 약하다.
- 2027년 채용 일정과 졸업예정자 자격은 공고 발표 후 다시 검증해야 한다.
- Wiki의 학습 전략은 아직 실제 취업 성과나 학습 유지율로 검증되지 않았다.

> 이 계획은 금융권·핀테크 Java 백엔드라는 현재 1차 목표에 맞춘 것이다. 좋은 개발 직장의 기준은 연봉뿐 아니라 코드리뷰 문화, 실제 개발 비중, 배울 수 있는 동료, 운영 책임, 근무 환경을 함께 확인해야 한다. 금융권 안에서도 회사와 팀에 따라 Java·C/C++·데이터·인프라의 비중이 다르므로 지원 직전 최신 공고로 조정한다.

# GNU-UNLV 글로벌 융합·혁신 프로그램 지원서 2차 초안

## 1. 자기소개

저는 예상치 못한 문제를 외면하지 않고, 해결책이 작동할 때까지 기술·제품·사업가설을 바꾸며 팀의 다음 실행을 만들어 온 예비 창업가입니다. `2025 글로벌 빅데이터·AI 교육 및 실무 체험 프로그램`의 4주 PBL에서 한국·인도·베트남 학생 5명으로 구성된 팀의 팀장을 맡아 Financial GraphRAG 개발을 이끌었습니다. 반도체 시장의 잠재 위험을 거시경제와 기업 요인으로 나누어 분석하도록 문제를 정의하고, 설계와 프롬프트 작성, 생성형 AI를 활용한 Python 코드 생성과 실행을 담당했습니다. 개발 도중 팀원들의 Windows·macOS 환경 차이로 프로젝트가 빌드되지 않는 문제가 발생하였습니다. 저는 개발 환경을 통일하기 위해 Docker 환경을 구축했습니다. 그 결과 모든 팀원이 같은 명령어로 프로젝트를 빌드하고 실행할 수 있었습니다. 영어로 세부 의도와 일정 기대를 맞추기 어려울 때는 매일 오전 스크럼을 열어 당일 과업과 진행 상황을 공유하며 팀의 실행 기준을 맞췄습니다.

같은 문제해결 태도를 창업에서도 이어 갔습니다. 2026년 4월 5인 창업팀 `CUEE`로 모두의 창업 1기에 지원했지만 탈락했고, 제품개발계획·초기 판로·지속 가능한 매출계획을 구체화해야 한다는 심사 의견을 받았습니다. 이에 팀원들에게 “실제로 우리가 고령 사용자라면 돈을 지불하면서까지 CUEE를 사용할까?”라고 물었고, 팀의 답은 “아니오”였습니다. 그래서 고령층에게 앱 사용법을 학습시키던 기존 아이디어에서, 학습 과정을 건너뛰고 실제 앱 위에서 다음 행동을 바로 안내하는 방식으로 피벗을 결심했습니다. 경쟁사 분석은 다른 팀원에게 위임하고, 개인에게는 무료로 제공하되 구매 전환률 향상을 근거로 기업과 제휴해 구매 성사당 수수료(CPS)를 받는 방향으로 비즈니스 모델을 수정했습니다. 저는 요구사항을 기능 단위로 나누고 자체 구축한 AI harness를 사용하여 구현한뒤 실기기를 연결하여 E2E 테스트를 반복해 MVP를 개발했습니다. 이후 창업 관련 대회에서 세 차례 수상하고 학생창업유망팀 300+ 도약과정 전국 400팀에 선정됐으며, 현재 모두의 창업 2차에 재지원하고 Play Store 심사 요건을 준비하기 위해 비공개 테스트 참여자를 모집하고 있습니다.

저는 창업가에게 가장 중요한 태도는 예기치 못한 문제를 외면하지 않고 해결책이 작동할 때까지 개선하며, 어제보다 나은 서비스를 만드는 것이라고 생각합니다. FPT에서는 기술적 장애를 공통 개발환경과 협업 기준의 문제로 풀었고, CUEE에서는 제품의 한계를 사용자 관점의 질문과 비즈니스 모델 수정으로 전환했습니다. 현재도 Threads 생성형 AI workflow를 운영해 팔로워 632명과 콘텐츠를 공유하는 한편, 멋쟁이사자처럼 14기 부대표·실리콘밸리 취업동아리 대표·GNU 개척리더스 창업서포터즈 2기로서 제가 겪었던 시행착오들을 주변의 사람들에게 공유하고 있습니다. 예기치 못한 문제 앞에서 팀장으로 해결방안을 찾고 다음 실행을 주도하는 것이 저의 창업가로서의 정체성입니다.

## 2. 지원동기

생성형 AI를 활용한 자동화 workflow를 실제로 운영하면서, 빠른 생성이 신뢰할 수 있는 결과를 보장하지 않는다는 한계를 경험했습니다. Threads에서 논문 활용 콘텐츠가 자동 게시된 뒤 참고자료를 직접 확인하던 중, 생성형 AI가 제시한 GitHub 링크가 `404 Not Found`이고 해당 저장소의 존재 여부도 확인할 수 없다는 사실을 발견했습니다. 그럼에도 AI는 이를 검증된 자료처럼 사용해 주장을 구성했습니다. 저는 게시물을 삭제하고 크롤링 과정을 점검해 workflow를 수정했지만, 오류를 사후에 발견하는 방식만으로는 부족했습니다. 이 경험을 통해 AI가 만든 결과물을 게시하기 전에 출처와 주장의 타당성을 검증할 수 있는 파이프라인을 만드는 것이 중요하다고 느꼈습니다.

CUEE에서도 비슷한 검증의 공백을 마주하고 있습니다. MVP와 수상 성과를 만들었지만, 실제 65세 이상 사용자가 어느 화면에서 멈추고 어떤 도움을 필요로 하는지 관찰한 경험은 아직 없습니다. 따라서 `생성형 AI 개론`의 출처 검증·사실 확인·환각 대응을 Threads workflow에 적용하고, `기업가적 창의성과 혁신`의 관찰 기법을 CUEE의 사용자 검증에 적용하고 싶습니다. 두 과목을 7주 동안 하나의 프로젝트 경험으로 결합하고, 아이디어와 검증 결과를 영어로 발표해 피드백받을 수 있다는 점이 지금 저에게 UNLV가 필요한 이유입니다.

저는 베트남 FPT 다국적 팀 프로젝트, GNU Buddy 44.23시간, 캐나다 TMU의 4주·100시간 영어 몰입 과정을 통해 해외 수업과 장기간 공동생활을 완주할 수 있음을 보여 왔습니다. 이제 해외 경험의 횟수를 늘리는 데서 그치지 않고, UNLV에서 얻은 검증 방법을 현재 프로젝트의 다음 성과로 연결하고자 합니다. 귀국 후에는 인근 노인복지시설에 협조를 요청해 65세 이상 사용자 10명을 예비 관찰하고, 그 결과를 현재 CUEE 앱과 비즈니스 모델에 반영하겠습니다. 이를 2027년 창업중심대학 예비창업자 사업화 지원에서 평가받을 다음 검증 자료로 발전시키겠습니다. 또한 UNLV에서 배운 기업가적 정신과 창의적 사고방식을 멋쟁이사자처럼·실리콘밸리 취업동아리·창업서포터즈 구성원들과 공유하겠습니다.

## 3. 학업계획서

저의 학업 원칙은 강의를 듣는 데서 멈추지 않고 `학습 → 실험 → 기록 → 개선`으로 전환하는 것입니다. UNLV에서 배운 검증 방법을 팀 프로젝트와 Threads·CUEE에 적용해 ① AI 콘텐츠 게시 전 검증표와 workflow, ② 고령 사용자 관찰표와 CUEE 앱 개선 결과, ③ 영어 발표와 동료 피드백 기록을 만들겠습니다.

- 1단계 — 문제 재정의(1~2주차)

생성형 AI의 출처 오류와 환각이 발생하는 원인을 배우고, Threads에서 발견한 링크 오류를 게시 전에 확인할 문제로 구체화하겠습니다. CUEE의 문제도 `고령층은 앱을 사용하기 어렵다`는 넓은 설명에서 `예매 과정에서 다음 행동을 찾지 못해 중단한다`는 관찰 가능한 가설로 좁히겠습니다.

- 2단계 — 근거와 사용자 검증 설계(3~4주차)

Threads 콘텐츠 10건의 링크 접근 여부, 자료 존재 여부, 주장과 출처의 일치 여부, 사람의 수정 내용을 기록하는 게시 전 검증표를 만들겠습니다. `기업가적 창의성과 혁신`의 관찰 및 시각화 기법을 활용해 과업 완료 여부, 소요시간, 잘못 누른 횟수, 도움 요청 횟수와 중단 화면을 기록할 CUEE 사용자 관찰표도 설계하겠습니다. 두 표는 Python의 Streamlit으로 입력 화면을 만들고 pandas로 CSV 데이터를 정리하겠습니다. 링크 접근 여부는 Requests로 자동 확인하되 주장과 출처의 일치 여부는 직접 대조하겠습니다.

- 3단계 — workflow와 현재 앱 개선(5~6주차)

검증표를 바탕으로 자료 수집, AI 생성, 링크·주장 확인, 사람의 승인과 게시를 연결한 Human-in-the-loop workflow를 만들겠습니다. 팀 프로젝트에도 같은 검증 기준을 적용하고, 설계한 관찰 항목을 기준으로 화면 강조와 음성 안내를 현재 CUEE 앱에 반영해 개선하겠습니다.

- 4단계 — 영어 발표와 다음 검증(7주차·귀국 후)

UNLV 최종 팀 프로젝트에서는 문제 정의와 AI 활용·검증 과정을 영어로 발표하고 동료 피드백을 기록하겠습니다. 귀국 후에는 인근 노인복지시설에 협조를 요청해 65세 이상 Android 사용자 10명에게 실제 결제와 개인 계정을 사용하지 않는 모의 예매 과업을 진행하겠습니다. 반복되는 중단 지점과 개선 우선순위를 찾아 현재 CUEE 앱과 비즈니스 모델을 수정하고, 그 결과로 2027년 창업중심대학 예비창업자 사업화 지원에 도전하겠습니다.

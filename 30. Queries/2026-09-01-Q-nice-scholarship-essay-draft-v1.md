# NICE 장학금 자기소개서 1차 초안

## 결론

5개 문항을 작성하기 전에 남은 차단 수준의 모호성은 없다. 행사 장소는 미확정이므로 특정 장소를 쓰지 않았고, 공식 성적증명서 발급과 Threads 계산 검산은 제출 전 확인 사항으로 남겼다.

## 1번 — 성장 스토리와 세 가지 키워드

공백 포함 342자 / 500자 이내.

저를 나타내는 세 키워드는 질문·축적·실험입니다. 2024년부터 2025년 1학기까지는 강의와 교재를 따라가다 막히면 친구와 교수에게 묻는 방식으로 공부했습니다. 전공 5과목을 한꺼번에 들은 2025년 1학기 평점이 3.42로 내려가자 학습법의 한계를 돌아봤습니다. Gemini Gem을 정답이 아닌 단계별 힌트를 주는 튜터로 설정했습니다. 먼저 풀고, 이해한 내용을 다시 설명해 검증하며 22학점 전부를 이수해 4.10을 받았습니다. 유익한 자료는 LLM Wiki에 연결해 축적하고, Threads에서는 반응 데이터를 다음 글에 반영합니다. 질문으로 파고들고, 지식을 쌓고, 결과를 실험하는 사람이 되었습니다.

## 2번 — 꿈, 목표, 실천 계획과 장학금 활용

공백·줄바꿈 포함 약 794자 / 1,000자 이내.

제 꿈은 금융 데이터에서 고객과 시장의 패턴을 발견해 서비스의 의사결정을 개선하는 금융 데이터 분석가가 되고, 장기적으로 분석 결과를 실제 금융 서비스에 구현하는 금융 IT 인재로 성장하는 것입니다. Threads 자동화에서 시스템 구현 자체보다 게시물 반응에서 패턴을 찾고 가설을 검증해 다음 글을 바꾸는 과정에 더 흥미를 느끼며 진로를 구체화했습니다. 다만 현재는 CSV·SQL 기초 집계 수준으로, 결측치 처리·통계적 검정·실험 설계·교란요인 통제가 부족합니다.

2026년 2학기에는 NICE 세션1에서 산업별 데이터 수집·가공·활용 사례를 조사하고 발표하겠습니다. SQLD를 취득하고, Threads 데이터를 동일한 72시간 관측창으로 재분석해 형식·주제·시간대별 차트와 재현 코드를 갖춘 보고서를 12월까지 완성하겠습니다. 장학금 200만 원은 NICE 행사 이동비 35만 원, SQLD·EDA·AB 테스트 교육 16만 5,500원, 분석 배포비 15만 원, 4개월 통학·식비 133만 4,500원에 사용하겠습니다.

2027년 1학기에는 NICE 실무 데이터 분석을 수료하고 ADsP에 응시하겠습니다. Upbit 공개데이터로 ‘거래량 급증 뒤 변동성이 확대되는가’를 검증하는 백테스트 파이프라인·대시보드·최종 보고서를 6월까지 만들겠습니다. 300만 원은 NICE 행사 35만 원, ADsP·백테스트 교육 24만 8,000원, 클라우드·도서·멘토링·발표 85만 원, 통학·식비 155만 2,000원에 배분하겠습니다. 장학금이 없다면 가족 부담을 줄이기 위해 유료교육·외부행사·장기 배포부터 축소해야 합니다.

## 3번 — 예상하지 못한 어려움과 극복 경험

공백 포함 447자 / 500자 이내.

2026년 5월 27일 GNU 개척리더스 창업 아이디어톤에서 최우수상을 받았지만, Q&A에서 “경쟁 서비스와 무엇이 다른가”라는 질문에 제대로 답하지 못했습니다. 팀장으로서 방문형 1:1 교육, 케어유, 현장 매표소를 조사하고 ‘실시간 실제 상황 보조·교육 기반 접근·대면 창구’라는 동일 기준으로 비교표를 다시 만들었습니다. 역할을 나눠 자료를 보완하고, 저는 발표 순서와 Q&A를 고치며 개발 진행과 발표를 맡았습니다. 그 결과 CUEE의 차별성을 ‘사용법을 미리 가르치는 것이 아니라 실제 앱 사용 순간에 다음 행동을 안내하는 서비스’로 명확히 설명했고, 6월 16일 경남권 창업동아리 심화교육에서 대상을 받았습니다. 이후에도 U300+ 도약과정의 세 차례 멘토링과 전시·네트워킹에 참여하며 개선을 이어갔습니다. 피드백은 방어할 대상이 아니라 다음 검증 기준으로 바꿔야 한다는 점을 배웠습니다.

## 4번 — 데이터 기반 의사 결정의 중요성

공백 포함 448자 / 500자 이내.

데이터는 직관을 없애는 정답이 아니라, 직관을 검증하고 다음 행동을 수정하는 근거라고 생각합니다. Threads 운영 초기에 여러 글 형식을 시도하며 게시물별 조회수·좋아요·재게시를 CSV에 모았습니다. ‘나쁜 요청/좋은 요청’ 형식이 반복해 높은 좋아요를 얻자 다음 콘텐츠에 적용했습니다. 이후 같은 72시간 관측창이 확보된 게시물만 다시 비교하고, 작성자 체인 답글을 제외한 독자 참여율을 ‘(좋아요+독자답글+재게시+인용)÷조회수’로 계산했습니다. 7월 15일 글은 (19+0+8+0)÷2,456=1.10%였습니다. 확인 가능한 동일 형식 32개의 초기·후기 중앙값은 1.01%에서 0.37%로 낮아져 형식 피로 가능성을 발견했습니다. 그러나 주제·게시시간·노출량이 달라 형식이 원인이라고 단정하지 않았습니다. 데이터는 결론을 꾸미는 숫자가 아니라 한계를 드러내고 다음 실험을 설계하는 기준입니다.

## 5번 — 데이터 관련 교육·수행 경험

공백 포함 448자 / 500자 이내.

현재 데이터 분석 관련 자격증·수상 실적은 없지만, 2026년 1학기 경상국립대학교 데이터베이스PBL 과목을 A0로 이수했습니다. Threads 자동화에서는 52개 게시물의 조회수·좋아요·재게시 데이터를 수집해 기초 비교하고, 반응이 좋은 형식을 다음 글에 반영했습니다. 학부연구에서는 Elasticsearch Java 파일 3,574개에서 추출된 메서드 호출 5,486개의 결과를 검토했습니다. unresolved 2,007개(36.58%)를 확인하고, 교수 피드백 후 단순한 test/source 분류, 외부 dependency 누락, 비정상 입력을 원인 후보로 정리했습니다. 분석 코드를 직접 작성하거나 개선안을 재실행한 단계는 아닙니다. 현재 CSV·SQL 구조화와 기초 집계·오류 분류는 가능하지만, 통계적 검정·실험 설계·인과 해석은 부족합니다. NICE 교육에서 이 간극을 보완하겠습니다.

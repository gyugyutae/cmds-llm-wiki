# GNU-UNLV 선발경쟁력 보강 진단

## 결론

현재 지원자는 프로그램 주제 적합성과 활동량이 강하다. 당락을 더 크게 바꿀 부분은 새 활동을 추가로 나열하는 것이 아니라, `실제 사용자 검증`, `AI 결과 검증`, `영어 발표 가능성`을 작고 확인 가능한 산출물로 만드는 일이다. 다만 2026-09-21이 접수 마감일이므로 가장 먼저 학적 자격과 이중 접수를 확인해야 한다.

## 공식 선발 구조

- 국제협력과 1차: 학적·직전학기 평균평점 1.75 이상·공인영어 기준 등 자격 심사
- 단과대학 2차: 전임교원 3명으로 구성된 위원회의 수학능력 심사, 총점 70점 이상
- IT공과대학 최대 2명
- 필수 서류 외 `AI·창업 등 관련 활동 실적 1부` 선택 제출 가능
- MY서비스 서류 제출과 Google Form 제출을 모두 완료해야 접수 인정

세부 배점표는 공고에 공개되지 않았다. 따라서 아래 경쟁력 평가는 지원서 문항, 선택 증빙, 강의 평가방식에 근거한 추론이다.

## 현재 강점

1. **주제 적합성**: FPT GraphRAG, Threads AI workflow, CUEE가 두 교과목과 직접 연결된다.
2. **실행의 연속성**: 해외 교육 수료에서 끝나지 않고 자동화·제품·창업 활동으로 이어졌다.
3. **수학·생활 완주 가능성**: FPT 수료, GNU Buddy 44.23시간, TMU 100시간·A-·출석률 93.75%, TOEIC 730이 있다.
4. **확산 능력**: 멋쟁이사자처럼 부대표와 실리콘밸리 취업동아리 대표라는 실제 공유 채널이 있다.
5. **지원 과정과의 직접 연결**: 정확성·환각·편향 검증과 관찰·페르소나·프로토타입이라는 학습 필요가 강의계획서와 일치한다.

## 주요 감점 위험

1. **최종 학기 자격 오해**: 현재 7번째 정규학기라는 기록은 파견 후 한 학기 수학 가능 조건과 맞아 보이지만, 포털 학년·학기 표기가 `4학년 2학기`로 해석될 가능성을 접수 전 확인해야 한다.
2. **CUEE 사용자 증거 부족**: 수상은 3회지만 65세 이상 실제 사용자의 행동 관찰과 효과 수치는 아직 없다.
3. **AI 검증 결과 부족**: GraphRAG와 Threads를 실행했지만 정확성·출처·환각을 정량 평가한 기록이 없다.
4. **영어 발표 증거의 공백**: FPT 최종 발표는 팀이 영어로 수행했으나 본인이 발표하지 않았고, TMU 팀은 한국인으로 구성됐다. TOEIC 730은 지원 자격은 충족하지만 토론·발표 능력의 강한 증거는 아니다.
5. **활동 나열 위험**: 해외 프로그램이 많다는 사실만 강조하면 `또 하나의 연수 수혜`로 읽힐 수 있다. 각 활동이 다음 실행으로 이어진 인과와 GNU 공동체에 돌려줄 계획이 보여야 한다.
6. **AI 코드 기여 과장 위험**: AI 생성 코드와 본인 판단·검증 범위를 구분하지 않으면 강의의 학업 정직성 원칙과 충돌할 수 있다.

## 우선순위별 행동

### P0 — 오늘 반드시 확인

- MY서비스와 Google Form 두 곳 모두 제출 완료 화면을 캡처한다.
- 재학증명서 또는 학사정보에서 현재 학기와 2027-1학기 수학 가능 여부를 확인한다. 표현이 모호하면 국제협력과 또는 IT공과대학 행정실에 바로 확인한다.
- TOEIC 730 성적의 유효기간과 원본 식별정보, 성적증명서·재학증명서·서약서 서명·보호자 서명을 확인한다.
- 선택 활동실적은 여러 파일이 아니라 심사자가 빠르게 읽을 수 있는 단일 PDF 1부로 만든다.

### P1 — 가장 큰 경쟁력 상승

#### 1. CUEE 소규모 사용자 관찰 2~3명

- 가능하면 65세 이상 참가자에게 실제 기기 또는 안전한 데모로 한 가지 예매 과업을 수행하게 한다.
- 도움 없이 완료 여부, 막힌 화면, 완료 시간, 도움 요청 횟수, 관찰 후 한 문장 피드백을 기록한다.
- 참가 동의와 개인정보 비수집 원칙을 지킨다.
- 표본이 작으므로 효과를 일반화하지 않고 `예비 관찰에서 발견한 문제`로만 사용한다.

이 증거는 CUEE를 수상한 아이디어에서 실제 사용자를 관찰하는 프로젝트로 바꾸며 기업가적 창의성 과목과 가장 직접적으로 연결된다.

#### 2. AI 결과 검증 미니 실험 10건

- FPT GraphRAG 또는 Threads workflow 중 하나를 고른다.
- 질문/주장 10건에 대해 원문 근거 존재 여부, 인용 정확성, 과장·환각 여부, 수정 전후를 표로 남긴다.
- 정확도처럼 보이는 비율을 사용할 때는 10건의 소규모 내부 점검임을 명시한다.
- README 또는 1쪽 보고서에 프롬프트, 기준, 실패 사례 2개, 사람이 최종 확인하는 절차를 기록한다.

이 증거는 `검증을 배우고 싶다`는 말에 더해, 이미 한계를 발견하고 첫 측정을 시작한 지원자라는 인상을 만든다.

#### 3. 영어 프로젝트 설명 증거

- 60~90초 동안 FPT 또는 CUEE의 문제·본인 역할·한계·UNLV에서 검증할 점을 영어로 설명한 영상을 촬영한다.
- 대본 낭독보다 핵심어만 보고 말하고, 공개 링크 또는 QR을 활동실적 PDF에 넣는다.
- 제출 양식이 외부 링크를 허용하지 않으면 억지로 넣지 않고 면접·추가 확인용으로 보관한다.

### P2 — 선택 활동실적 1부의 구성

1. 한 줄 정체성과 `FPT → Threads/CUEE → UNLV → 교내 확산` 타임라인
2. FPT: 수료증, GitHub QR, 문제 정의·Docker·스크럼에서의 본인 역할
3. CUEE: 피벗 전후, MVP 화면, 3회 수상, Play Store 진행 상태, 가능하면 사용자 관찰 결과
4. Threads: workflow 도식, 게시물/팔로워 원본 화면, 정확성 검증 미니 실험
5. 해외 수학 준비: TMU 성적·출석, GNU Buddy, TOEIC 730은 한 페이지에 압축
6. 귀국 후 확산: 멋쟁이사자처럼 세션, 실리콘밸리 취업동아리 영어 발표, Threads 콘텐츠, 성과공유회

각 사례는 `문제 → 본인 행동 → 결과 → 증빙 → UNLV에서 다음에 검증할 것` 다섯 칸으로 통일한다. 증빙 없는 수치나 과도한 수식어는 제외한다.

## 하지 않는 편이 나은 것

- 마감 직전에 관련성 낮은 자격증이나 활동을 추가하는 것
- 해외 경험의 개수만 반복하는 것
- CUEE 수상 3회를 사용자 검증 성공으로 표현하는 것
- AI가 생성한 코드를 모두 직접 개발했다고 표현하는 것
- FPT 영어 발표를 본인이 발표한 것처럼 쓰는 것
- 2~3명의 예비 관찰 결과를 시장 전체의 효과로 일반화하는 것

## 경쟁력 판단

활동의 주제 적합성과 연속성은 강한 편이지만, 실제 경쟁자의 성적·영어·지원서는 알 수 없어 합격 확률을 수치화할 수 없다. 현재 상태에서도 경쟁 가능한 서사이나, `사용자 관찰 1건 + AI 검증표 1건 + 읽기 쉬운 단일 증빙 PDF`가 추가되면 다른 지원자와 가장 선명하게 구분될 가능성이 크다.

> [!note] Bias Check
> 세부 수학능력 심사 배점은 공개 공고에서 확인되지 않았다. 따라서 특정 활동이 실제로 몇 점을 올린다고 단정하지 않으며, 강의 목표·평가 방식·제출 서류에 직접 대응하는 증거를 우선순위로 제시했다.

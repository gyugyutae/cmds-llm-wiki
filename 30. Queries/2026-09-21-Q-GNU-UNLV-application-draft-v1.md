# GNU-UNLV 글로벌 융합·혁신 프로그램 지원서 1차 초안

> [!info] Draft Status
> 이 문서는 2026-09-21 논의를 반영한 1차 초안이다. HWP 실제 입력 공간과 사용자 톤에 맞춰 문장 길이·강조 순서를 추가로 조정한다.

## 선발 전략

전체 문항의 중심 정체성은 `배움을 다음 프로젝트와 성과로 전환하는 AI·창업 실행형 소프트웨어공학도`다.

- 실행: FPT GraphRAG, Threads workflow, CUEE MVP·피벗·수상
- 수학 준비: FPT 다국적 협업, GNU Buddy 44.23시간, TMU 100시간·A-·93.75%, TOEIC 730
- 필요성: AI 결과의 정확성·환각·편향 검증과 CUEE의 사용자·페르소나·사업 검증 부족
- 확산: CUEE, 멋쟁이사자처럼, 실리콘밸리 취업동아리, Threads, 성과공유회

## 1. 자기소개

저는 배운 내용을 일회성 경험으로 남기지 않고 다음 프로젝트와 성과로 전환해 온 소프트웨어공학도입니다. 2025학년도 동계 베트남 다낭 FPT University의 4주 PBL에서 한국·인도·베트남 학생 5명으로 구성된 팀의 팀장을 맡았습니다. 전체 금융시장을 다루기보다 변동성과 산업 사이클, 공급망 위험에 민감한 반도체 시장으로 범위를 좁혀, 거시 환경과 기업 요인을 연결해 잠재 위험을 분석하는 Financial GraphRAG을 제안했습니다. 문제 정의와 설계, 프롬프트, 생성형 AI를 활용한 Python 코드 생성과 실행을 담당했고, Windows와 macOS를 사용하는 팀원들이 같은 환경에서 개발할 수 있도록 Docker 환경을 구성했습니다. 영어로 속도와 일정에 대한 기대를 조율하기 어려웠지만, 매일 업무 시작 전 스크럼을 열어 당일 과업과 진행 상태를 공유하며 협업 기준을 맞춰 갔습니다.

귀국 후에는 실행을 두 가지 방향으로 확장했습니다. 2026년 3월부터 생성형 AI로 논문 활용 사례를 조사하고, 콘텐츠를 생성·발행하며, 반응 데이터를 다음 기획에 반영하는 Threads 워크플로를 구축했습니다. 여러 글 형식을 비교해 반응이 좋은 형식을 반복 운영했고, 2026년 8월 기준 650명의 팔로워로 이어졌습니다. 동시에 CUEE 팀장으로 창업 활동을 시작했습니다. `모두의 창업` 1차 탈락 후 “내가 실제 노인이어도 이 앱을 쓸까?”라는 질문을 팀에 던졌고, 앱 사용법을 학습시키는 `배우담`에서 실제 앱 위에서 다음 행동을 안내하는 `CUEE`로 피벗했습니다. 이후 MVP와 Play Store 출시 준비, 창업 경진대회 3회 수상으로 이어 갔습니다. 저의 강점은 생성형 AI를 빠르게 쓰는 것에서 멈추지 않고, 문제를 정의하고 협업 환경을 만들며 배움을 반복 가능한 실행으로 전환하는 점입니다.

## 2. 지원 동기

저는 생성형 AI를 사용해 국제 팀 프로젝트와 자동화 워크플로를 실제로 운영해 봤지만, 빠른 생성이 곧 신뢰할 수 있는 결과를 의미하지는 않는다는 한계도 발견했습니다. Threads 워크플로에서 논문 정보를 콘텐츠로 변환하며, AI 결과의 출처·정확성·환각·편향을 체계적으로 평가하는 방법이 더 필요하다고 느낀 이유입니다. CUEE 역시 아이디어를 피벗하고 MVP를 만들었지만, 실제 65세 이상 사용자가 어디에서 멈추는지 관찰하고 구체적인 페르소나와 사업 가설을 검증하는 단계는 아직 부족합니다.

GNU-UNLV 프로그램은 이 두 부족함을 하나의 프로젝트에서 보완할 수 있는 과정입니다. `생성형 AI 개론`의 프롬프트 설계·반복 테스트, 출처 검증, 환각 대응, 멀티모달 활용, Human-in-the-loop 워크플로, 윤리·개인정보·저작권 교육은 제가 이미 만든 AI 자동화를 검증 가능한 시스템으로 발전시키는 데 필요합니다. `기업가적 창의성과 혁신`의 관찰, 시각화, 유연한 사고, 페르소나, 프로토타입과 혁신 토너먼트는 CUEE를 기술 데모에서 사용자 문제를 검증하는 제품으로 발전시키는 데 필요합니다. 생성형 AI의 검증 가능성과 기업가적 문제 해결을 하나의 프로젝트에서 결합하는 경험을 얻고 싶습니다.

저는 베트남 FPT의 다국적 팀 프로젝트, 2026학년도 1학기 GNU Buddy 44.23시간, 캐나다 TMU의 4주·100시간 영어 몰입 과정을 통해 해외 수업과 팀 활동을 안정적으로 수행할 수 있음을 보였습니다. 이제는 해외 프로그램을 경험하는 것을 넘어, 그 경험을 현재 진행 중인 프로젝트의 다음 검증으로 연결하고자 합니다. `모두의 창업` 2차에 선발된다면 UNLV에서 배운 관찰·페르소나·AI 검증 방법을 CUEE의 후속 제품 검증에 적용하겠습니다. 선발 결과와 관계없이 사용자 검증과 Play Store 출시 후 개선은 계속할 계획입니다. 귀국 후에는 이 과정을 멋쟁이사자처럼 세션, 실리콘밸리 취업동아리, Threads 콘텐츠와 학교 성과공유회로 확산하겠습니다.

## 3. 학업계획서

저의 학업 원칙은 수업을 듣는 데서 멈추지 않고, 매주 배운 내용을 CUEE와 제 AI 워크플로에 적용해 `인풋 → 실험 → 아웃풋 → 성찰`의 기록을 남기는 것입니다. CUEE는 개인 적용 사례로 사용하고, 최종 팀 프로젝트에서는 팀원의 동의와 피드백을 받아 CUEE 또는 같은 문제의 확장 아이디어를 제안하겠습니다.

### 1주차 — 역량 진단과 문제 재정의

생성형 AI의 기초·가능성·한계를 배운 후, FPT GraphRAG·Threads·CUEE에서 AI에게 맡긴 일과 제가 판단·검증한 일을 구분한 자가 진단표를 작성하겠습니다. 창업적 창의성 수업에서는 CUEE의 문제를 `노인이 앱을 못 쓴다`가 아니라 `예매 중 다음 행동을 찾지 못해 중단한다`는 관찰 가설로 다시 정의하겠습니다.

### 2주차 — 프롬프트 실험과 사고의 전환

맥락·역할·과업·제약·예시·출력 형식을 달리한 프롬프트를 반복 테스트하고, 답변 품질과 실패 유형을 기록하겠습니다. 창의성 기법 보고서에서는 기존의 `사용법 교육`과 `실제 사용 중 안내`를 다른 관점에서 비교하고, 사용자에게 추가 학습을 요구하지 않는 대안을 탐색하겠습니다.

### 3주차 — 출처 검증과 사용자 관찰

AI를 활용한 글쓰기·요약·조사에서 원문 대조, 출처 확인, 환각 판별 절차를 Threads workflow에 적용하겠습니다. 동시에 관찰과 시각화 기법을 활용해 CUEE 사용자가 예매 흐름에서 멈출 수 있는 지점, 필요한 도움, 중단 이유를 관찰할 기록표와 페르소나 초안을 만들겠습니다.

### 4주차 — 멀티모달 안내와 유연한 발상

시각·음성·텍스트 입출력을 비교해 글자를 읽기 어렵거나 복잡한 화면에서 다음 행동을 찾기 어려운 사용자에게 어떤 안내 조합이 적합한지 탐색하겠습니다. 이미지 저작권·접근성·표현성을 함께 검토하고, 일반적인 발표 도구를 쓰지 않는 `I am...` 프로젝트를 통해 제 AI·창업 성장 과정을 새로운 매체로 표현하겠습니다.

### 5주차 — 반복 가능한 workflow와 프로토타입

아이디어, 자료 수집, AI 생성, 사람의 검토, 테스트, 수정을 연결한 workflow map을 작성하겠습니다. Threads에서 사용한 자동화 경험을 토대로 사용자 피드백이 CUEE의 요구사항·테스트·개선안으로 전환되는 구조를 설계하겠습니다. 연관 결합·브레인스토밍·Deep Dive를 활용해 개선 프로토타입을 제작하겠습니다.

### 6주차 — 윤리·개인정보·페르소나 검증

CUEE가 Android 접근성 권한을 사용하는 만큼 화면·음성·예매 정보를 저장하지 않는 원칙, AI가 확신하지 못하는 버튼을 안내하지 않는 원칙, 결제 전 안내를 종료하는 원칙을 윤리·보안 사례 분석과 연결해 검토하겠습니다. 페르소나 탐색과 동료 피드백을 통해 `노인`이라는 넓은 대상을 구체적인 초기 사용자와 행동 조건으로 좁히겠습니다.

### 7주차 — 영어 발표와 다음 검증 계획

팀원과 합의한 AI 기반 문제 해결안을 혁신 토너먼트와 최종 프로젝트에서 영어로 발표하겠습니다. 기능 데모만 보여주지 않고, 문제 정의, AI 활용 범위, 출처·환각 검증, 사용자 가설, 윤리적 한계, 남은 검증 과제를 함께 문서화하겠습니다. 동료 피드백을 받아 개선 우선순위와 귀국 후 8주 실행 계획을 수립하겠습니다.

### 귀국 후 적용과 확산

수업에서 만든 프롬프트 실험 기록, workflow map, 페르소나, 윤리 체크리스트와 프로토타입을 CUEE의 출시 후 개선과 사용자 검증에 적용하겠습니다. 멋쟁이사자처럼에서는 `AI 결과를 그대로 쓰지 않고 검증 가능한 workflow로 만드는 방법`을 세션으로 공유하고, 실리콘밸리 취업동아리에서는 영어 프로젝트 발표와 피드백 활동으로 재구성하겠습니다. Threads에서는 생성형 AI의 정확성·편향·윤리를 실제 workflow 사례로 콘텐츠화하고, 학교 성과공유회에서는 `배움 → 적용 → 피드백 → 개선`의 전체 과정을 공유하겠습니다.

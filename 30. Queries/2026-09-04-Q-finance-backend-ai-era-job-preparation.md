# AI 시대 금융권·핀테크 백엔드 취업 준비 정리

## 현재 조건

- 경상국립대학교 소프트웨어공학과 4학년 취업준비생
- 목표: 금융권·핀테크의 Java 백엔드 또는 거래 인프라 직무
- 2026년 2학기: 18학점
- 2027년 1학기: 캡스톤 1과목, 3학점 예정
- 2027년 8월 졸업 예정
- 자격증 계획: 토익스피킹 → SQLD → 정보처리기사
- 현재 가장 큰 과제: 자격증 수집보다 직접 설명·수정·검증 가능한 Java 구현 증거 만들기

---

## 핵심 결론

AI 때문에 개발자 채용이 사라진다고 단정할 수는 없다. 다만 경기침체와 투자 위축, 팬데믹 시기의 과잉채용 조정, 생성형 AI 확산이 함께 작용하면서 신입 채용의 문턱이 높아졌다. 단순 CRUD 작성과 강의 복제 프로젝트의 가치는 낮아지고, 다음 능력을 증명하는 지원자가 유리해지는 방향이다.

1. 문제와 제약을 직접 정의한다.
2. Java·Spring·DB의 기본 동작을 설명한다.
3. AI가 만든 코드의 오류를 발견하고 수정한다.
4. 테스트·로그·수치로 결과를 검증한다.
5. 금융 데이터의 정확성과 장애 복구를 책임진다.
6. 기술 선택과 실패 과정을 다른 사람에게 설명한다.

소프트웨어정책연구소는 생성형 AI가 단순 반복 업무와 초급 역할에 영향을 줄 수 있지만, 개발자의 본질적인 역량이 사라지기보다 통합적 시스템 설계, 문제해결, 협업, AI 결과 판별과 위험 관리가 더 중요해질 것으로 전망했다.

김규태의 현실적인 포지셔닝은 다음과 같다.

> AI를 전 과정에서 활용하되, 금융 거래의 요구사항과 실패 조건을 직접 정의하고 생성 결과를 설명·수정·테스트하여 최종 결과에 책임지는 Java 백엔드 개발자 지망생

## 채용 공고에서 확인한 공통 역량

2026년 신한은행 디지털/ICT 채용은 프로그래밍, 알고리즘, 데이터 관리, 네트워크, 관계형 데이터베이스를 필요 역량으로 제시했다. 뱅킹서비스 개발 직무 코딩테스트는 알고리즘 4문항과 SQL 1문항으로 안내됐다.

토스뱅크 서버 개발 공고는 Java/Kotlin과 Spring, 트랜잭션과 데이터 정합성, 이자·금리·정산 같은 금액 흐름, 복잡한 금융 정책, 예외 상황과 장애 대응을 강조한다.

이를 취업 준비 항목으로 바꾸면 다음과 같다.

| 영역 | 준비할 내용 | 증거 |
|---|---|---|
| Java | OOP, 컬렉션, 예외, 불변 객체, 동시성, JVM 기초 | 직접 설명 가능한 코드와 JUnit 테스트 |
| Spring | DI, MVC 흐름, AOP·프록시, 트랜잭션, 검증, 보안 | API와 트랜잭션 실패 테스트 |
| DB·SQL | JOIN, 집계, 윈도 함수, 모델링, 인덱스, 격리 수준, 잠금 | SQL 풀이, ERD, `EXPLAIN`, 동시성 재현 |
| CS | 자료구조·알고리즘, OS, 네트워크 | Java 코딩테스트와 기술 설명 |
| 금융 도메인 | 주문·이체 상태, 원장, 정합성, 멱등성, 대사, 감사 | 실패·중복·복구 시나리오 |
| 운영 | 로그, 모니터링, 배포, 장애 분석, 성능 | 재현 명령과 before/after 수치 |
| AI 협업 | 초안 생성, 반례 탐색, 코드 리뷰, 검증 | `AI gave / I decided / I verified` 기록 |
| 소통 | 설계 근거, 협업, 기술 설명 | README, ADR, PR, 2분 발표와 면접 회고 |

## 책 선택

### Java 기본기가 있는 경우

첫 책은 `스프링 부트 4 개발자 되기 + AI: 자바 편`을 사용한다. Spring Boot, JPA, 테스트, 인증, 배포의 전체 흐름을 빠르게 경험하는 용도다. AI 부분보다 Java·Spring·JPA·테스트를 먼저 학습한다.

### Java 기본기가 부족한 경우

`혼자 공부하는 자바 개정판`처럼 Java 21을 반영한 입문서로 클래스, 인터페이스, 컬렉션, 예외 처리와 객체지향을 먼저 보강한다.

### 구매 원칙

- 한 번에 여러 권을 사지 않는다.
- 한 장을 읽을 때 프로젝트 기능 하나로 변환한다.
- 프로젝트 MVP를 만든 뒤 DB가 실제로 막힐 때 `Real MySQL 8.0 1권`의 인덱스·트랜잭션·잠금 부분을 추가한다.
- 책 완독을 프로젝트 시작의 선행조건으로 두지 않는다.

## 대표 포트폴리오 한 개

### 가칭: Reliable Financial Transaction Lab

계좌이체·거래원장 또는 국내주식 현물 주문 중 하나를 좁은 범위로 선택한다. 공통 핵심은 금융 화면이 아니라 **정확성, 중복 방지, 상태 전이, 복구, 성능**이다.

면접용 한 문장:

> 중복 요청과 장애 상황에서도 거래 정합성을 보존하고, 동시성·복구·부하 조건을 테스트해 p99 latency와 실패율을 개선한 Java 금융 백엔드 시스템을 만들었습니다.

### 최소 기능

1. 회원·계좌와 입금·출금·이체 또는 주문 생성·조회
2. 잔액 부족, 거래 한도, 잘못된 상태 전이 거부
3. 불변 거래원장과 잔액·체결 정합성 검증
4. idempotency key를 통한 중복 요청 방지
5. 동시 요청에서 낙관적·비관적 잠금 비교
6. 실패 거래 복구와 일별 대사
7. 인증·인가, 감사 로그, 개인정보 마스킹
8. 단위·통합·동시성·부하 테스트
9. Docker 실행 환경과 CI 자동 테스트
10. 아키텍처, ERD, 시퀀스, 실패·개선 기록

### 처음에는 제외할 것

- 불필요한 MSA
- 사용 이유를 설명할 수 없는 Kafka·Redis·Kubernetes
- 실제 금융기관 또는 거래소 연동
- AI 챗봇을 억지로 붙이는 기능
- 해외주식·파생상품 등 범위를 크게 만드는 기능

기본 DB 트랜잭션으로 정확성을 먼저 확보하고, 한계가 재현될 때만 추가 기술을 도입한다.

### 프로젝트가 답해야 할 질문

- 같은 요청이 두 번 전송되어도 한 번만 처리되는가?
- 동시에 여러 출금 또는 주문이 발생해도 잔액이 음수가 되지 않는가?
- 서버가 저장 직후 종료되면 어떤 상태가 남고 어떻게 복구하는가?
- 거래원장 합계와 잔액이 어긋난 것을 어떻게 탐지하는가?
- 어떤 인덱스를 만들었고 실행계획이 어떻게 달라졌는가?
- 평균 응답시간과 p99가 왜 다르며 병목은 어디였는가?
- AI가 작성한 부분 중 무엇을 직접 수정하고 검증했는가?

## AI 사용 규칙

AI 사용을 숨기거나 금지하는 것이 목표가 아니다. 결과의 소유권을 확보하는 것이 목표다.

```text
요구사항과 불변조건을 직접 작성
→ 핵심 흐름을 작은 단위로 분해
→ 먼저 예상 결과와 실패 조건 작성
→ AI로 구현 후보·반례·테스트 보조
→ 코드 diff 검토
→ 정상·경계·실패·동시성 테스트
→ 원인을 설명하고 직접 수정
→ 재현 명령과 결과 기록
```

각 기능의 기록에는 다음 네 항목을 남긴다.

- `AI gave`: AI가 제안하거나 생성한 것
- `I decided`: 본인이 선택한 요구사항과 설계
- `I verified`: 본인이 실행한 테스트와 측정
- `Unknown`: 아직 설명하거나 검증하지 못한 부분

실제 개인정보, API 키, 금융 거래 데이터는 공개 AI 도구에 입력하지 않는다.

## 자격증 로드맵 평가

기존 `certification-roadmap-2026-2027.md`는 시험 충돌을 줄이는 일정표로는 적절하지만 취업 준비의 중심축으로 쓰기에는 부족하다.

### 유지할 것

- 2026년 9월 토익스피킹 종료
- 2026년 11월 SQLD 응시
- 기말고사 후 정보처리기사 필기 시작
- SQLD와 정보처리기사를 동시에 집중하지 않기
- 실기가 캡스톤·채용과 겹치면 여름으로 미루기

### 보완할 것

- 토익스피킹 목표 점수와 재응시 종료 기준 설정
- 부산 시험의 실제 시간과 시험장은 접수 화면에서 확인
- 2027년 정보처리기사 일정은 공식 발표 전까지 예상치로 표시
- 정보처리기사 응시자격과 졸업예정 증빙 확인
- 자격증과 별도로 프로젝트·알고리즘·SQL의 주간 최소 시간 고정
- 2027년 2월까지 지원 가능한 상태를 완료 기준으로 설정

### 우선순위

1. 토익스피킹과 SQLD를 짧게 종료한다.
2. Java 알고리즘과 SQL을 매주 유지한다.
3. 2026년 12월까지 금융 프로젝트 v1을 만든다.
4. 겨울방학에 동시성·장애·성능을 심화한다.
5. 2027년 2월까지 이력서와 포트폴리오를 완성한다.
6. 3월부터 지원하며 캡스톤과 정보처리기사 실기를 병행한다.

추가 자격증은 목표 공고에서 명시적 가점을 확인하기 전까지 늘리지 않는다.

## 코딩테스트 전략

## 지원 전략

대형 은행과 대표 핀테크만 지원하면 채용 확률이 지나치게 낮아진다. 포트폴리오 서사는 하나로 유지하면서 지원 범위를 세 층으로 나눈다.

| 구분 | 지원 대상 |
|---|---|
| 상향 | 시중은행, 인터넷은행, 대형 핀테크, 대형 증권사 |
| 적정 | 카드·보험·증권 IT, 금융 IT 자회사, PG·결제사 |
| 진입 | 금융 솔루션사, 금융 SI, 중소 핀테크, 체험형·현장실습 인턴 |

1년 동안 목표기업 40~50개를 조사하고 최소 30개에는 지원한다. 회사별로 완전히 다른 포트폴리오를 만들지 않고, 공고에 따라 계정계·결제·주문·성능 중 강조점만 조정한다.

공고를 볼 때 회사 이름보다 먼저 다음을 확인한다.

1. 2027년 8월 졸업예정자가 지원 가능한가?
2. 체험형인가, 즉시 입사가 필요한 채용연계형인가?
3. 코딩테스트에 알고리즘과 SQL이 포함되는가?
4. 개발·인프라·보안 중 목표 직무와 가까운가?
5. 근무지와 풀타임 일정이 학업과 양립 가능한가?

탈락을 기록으로 바꾼다.

- 서류 탈락이 반복되면 이력서의 증거와 직무 일치도를 수정한다.
- 코딩테스트 탈락은 문제 유형·시간 부족·구현 오류로 분류한다.
- 면접 탈락은 답하지 못한 기술·도메인·행동 질문을 복기한다.

## 2027년 2월 지원 준비 완료 기준

- [ ] Java로 제한 시간 내 알고리즘 문제를 풀고 복잡도를 설명한다.
- [ ] JOIN·집계·서브쿼리·윈도 함수 SQL을 직접 작성한다.
- [ ] Spring 요청 흐름과 `@Transactional`의 프록시 동작을 설명한다.
- [ ] 인덱스와 실행계획을 프로젝트 쿼리로 설명한다.
- [ ] 동시 거래 문제를 재현하고 잠금 선택을 설명한다.
- [ ] 동일 요청을 여러 번 보내도 중복 처리되지 않음을 테스트한다.
- [ ] 장애 또는 성능 개선 사례가 최소 하나 있다.
- [ ] 프로젝트 전체 코드를 설명·수정·재실행할 수 있다.
- [ ] AI 기여와 본인 판단·검증 범위를 공개할 수 있다.
- [ ] 프로젝트를 2분과 15분 버전으로 발표할 수 있다.
- [ ] 1페이지 기본 이력서와 지원 회사별 수정본이 있다.
- [ ] 최소 3회의 모의 기술면접을 완료했다.

## Quality Gaps

- 현재 Java 직접 구현 수준을 보여주는 진단 결과가 없다.
- 금융 프로젝트의 최종 범위가 계좌이체인지 주식 주문인지 아직 확정되지 않았다.
- 토익스피킹 목표 점수와 종료 기준이 정해지지 않았다.
- 목표 기업별 2027년 지원 자격과 전형 일정은 공고 발표 후 다시 확인해야 한다.
- 코딩테스트 풀이 로그와 SQL 실습 기록이 아직 Wiki에 없다.
- 기존 프로젝트는 AI 작성 범위가 커서 새 Java 프로젝트의 검증 가능한 증거가 필요하다.
- Core Context의 기존 `3학년` 상태와 이번 대화의 `4학년` 진술이 충돌했으며, 이번 대화의 최신 자기보고를 기준으로 갱신했다.

> [!note] Bias Check
> 금융권과 핀테크 안에서도 전통 은행, 인터넷은행, 증권사, 결제사, 금융 SI의 채용 기준은 다르다. 이 문서는 2025~2026년 일부 공고와 현재 사용자 조건을 바탕으로 만든 실행 전략이며, 특정 기술이 모든 회사의 필수조건이라는 뜻이 아니다. 지원 직전 최신 공고로 졸업요건, 어학, 자격증, 코딩테스트와 기술 스택을 다시 확인한다.

# 은행권 백엔드 인턴·신입 준비도와 핵심 격차

## 결론

김규태의 학점 3.7/4.5와 소프트웨어공학 전공은 은행권 IT 지원에서 현재 병목이 아니다. TOEIC 730과 자격증 없음은 서류 차별력이 약한 요소이지만 보완 가능하며, 이것만 먼저 올린다고 합격 준비가 되지는 않는다.

현재 가장 부족한 한 가지는 **Java·Spring·SQL로 직접 구현하고, CS 원리와 실패 조건을 설명·수정·테스트할 수 있다는 독립적인 백엔드 증거**다. 기존 대표 프로젝트는 문제의식·AI 활용·리더십 소재는 있으나 코드의 상당 부분을 AI가 작성해 직접 구현력 증거로 쓰기 어렵다. 최근 면접 복기에서도 자료구조 선택 전에 필요한 연산을 정의하지 못하고, TCP 전달 특성과 거래 원자성을 혼동하는 등 `외운 개념을 상황에 적용하는 CS 기본기`가 약하게 확인됐다.

이 하나의 공백이 서류의 직무적합성, SQL 코딩테스트, 기술면접, 프로젝트 방어를 동시에 약하게 만든다.

## 최근 은행권 채용선

| 영역 | 인턴 지원 가능선 | 신입 경쟁선 | 김규태 현재 | 판정 |
|---|---|---|---|---|
| 학력·학점 | 공고 자격 충족, 전공 기초 | 3점대 중후반이면 별도 약점이 아닌 경우가 많음 | 소프트웨어공학, 3.7/4.5 | 충분 |
| 영어 | 요구되는 유효 성적 1개 | TOEIC 800대 또는 OPIc/TOEIC Speaking 중상위는 서류 보완 | TOEIC 730 | 지원 가능성이 있으나 차별력 낮음 |
| 자격증 | 필수 아닌 경우가 많음 | 정보처리기사·SQLD는 보완재, 회사별 실제 우대 목록 확인 | 없음 | 보조 약점 |
| 알고리즘 | 프로그래머스 Lv.2를 시간 안에 안정적으로 해결 | 백준 실버 상위~골드 하위 문제를 풀이·복잡도까지 설명 | Python 프로그래머스 2단계 학습 중 | 객관 기록 필요 |
| SQL | JOIN·집계·서브쿼리 기본 문제 독립 해결 | 코딩테스트 SQL을 놓치지 않고 프로젝트 쿼리·인덱스 설명 | 직접 작성 경험 거의 없음 | 위험 |
| Java·Spring | CRUD API를 직접 작성·실행·설명 | 트랜잭션·예외·테스트·동시성까지 방어 | 2026-09-12 기초 학습 시작 | 가장 큰 위험 |
| CS | 자료구조·DB·네트워크·OS 기본 정의 | 상황에 맞는 선택과 trade-off 설명 | 실제 면접에서 적용형 오개념 다수 확인 | 위험 |
| 프로젝트 | 작동하는 팀/개인 프로젝트에서 본인 기여 명확 | 실패·성능·정합성·배포가 재현되는 대표 프로젝트 | 기존 코드는 AI 작성 비중이 큼 | 가장 큰 위험 |
| 금융·고객·협업 | 지원동기와 팀 경험 | 금융 서비스·고객·조직 적합성까지 연결 | 투자 관심과 리더십 소재는 있음 | 강점 후보, 증빙 보강 |

위 `지원 가능선`과 `경쟁선`은 공식 합격 커트라인이 아니라 최근 공고·공개 후기와 현재 사용자 맥락을 합성한 실무 목표다. 은행별·회차별 차이가 크다.

## 공식 공고에서 확인된 요구

- 우리은행 2026년 하반기 TECH는 C·Java·JavaScript·SQL 또는 Spring 등의 개발 역량을 요구했고, 알고리즘·SQL 코딩테스트와 포트폴리오 면접을 함께 운영했다. 이 회차는 2027년 2월까지 졸업 가능한 사람만 신입 지원이 가능했고, 연수 후 약 1년 영업점 근무 뒤 IT·디지털 본부 배치를 안내했다.
- 신한은행 2026년 디지털·ICT 뱅킹서비스 개발은 Java 등 프로그래밍, 알고리즘·데이터 관리·네트워크, 관계형 DB 활용을 요구했다. 온라인 코딩테스트는 알고리즘 4문항과 SQL 1문항이었다.
- 하나은행 2026년 체험형 AI·ICT 인턴은 플랫폼·채널, 계정계·코어뱅킹 개발을 포함했고, 2027년 2월 이후 졸업예정자도 `재학`으로 지원할 수 있도록 했다. 영어 성적 1개와 풀타임 근무 가능성이 필요했다.

은행 IT는 항상 입사 즉시 순수 백엔드 팀에서 개발만 하는 직무가 아니다. 영업점 순환, 본점 OJT, 운영 업무와 배치 가능성을 회사별로 확인해야 한다.

## 공개 합격 사례

공개 후기는 표본이 작고 강한 합격자가 글을 남기는 자기선택 편향이 있다. 평균이나 필수 조건으로 해석하지 않는다.

1. **KB국민은행 2025년 하반기 IT 최종합격**: 제조업 문제해결 경험, SSAFY 개발 프로젝트, Kubernetes 인프라 경험, 정보처리기사·ADsP·SQLD. 알고리즘 3문항+SQL 1문항을 무리 없이 풀었고 체감 난이도를 백준 실버 상위~골드 하위로 기록했다. 핵심은 스펙 개수보다 자신의 경험을 KB의 클라우드·디지털 전환과 연결한 서사였다.
2. **하나은행 2025년 상반기 디지털·ICT 최종합격**: 백엔드 경험, 부트캠프 회고팀 팀장, 프로젝트 성취를 금융 IT 목표와 연결했다. 구현 3문항+SQL 2문항 중 약 4문항을 해결했고, 실무·PT·조직적합성 면접에서 금융 관심과 협업 태도를 함께 방어했다.
3. **하나은행 2026년 AI·ICT 인턴 최종합격 상단 사례**: 소프트웨어 복수전공, 4.07/4.5, 핀테크 보조 6개월과 스타트업 개발 인턴 6개월, AWS SAA·정보처리기사·SQLD, OPIc IH·TOEIC 900+, 해커톤 수상. 코딩테스트를 약 4.5/5 해결했다고 추정했다. 강한 사례이지 모든 합격자의 최소선은 아니다.

세 사례의 공통점은 `코딩테스트를 실제로 통과할 수 있는 구현력`, `본인 기여를 설명할 프로젝트·인턴`, `은행과 고객을 이해한 지원동기`다. 자격증과 높은 영어는 이 핵심을 보강하지만 대체하지 않는다.

## 김규태의 우선순위

### 1순위 — 직접 소유한 Java 금융 백엔드

8주 안에 주문·계좌 MVP를 만든다. 완료는 기능 수가 아니라 아래 증거로 판정한다.

- Java·Spring Boot·MySQL로 주문 생성·조회·취소와 잔액·보유수량 검증
- 정상·실패·경계·중복·동시 주문 JUnit 테스트
- 멱등성 키와 transaction 경계를 설명하고 실패를 재현
- 인덱스 적용 전후 `EXPLAIN`, 부하 테스트 p95·p99 한 사례
- Docker·CI·재현 README
- 핵심 기능을 AI 답 없이 설명하고 30분 안에 작은 요구 변경
- `AI gave / I decided / I verified / Unknown` 기록

### 2순위 — 알고리즘과 SQL 통과선

- Python으로 알고리즘 3문항+SQL 1문항, 120분 모의시험을 격주 실시
- 두 회 연속 3문항 이상 완전 통과를 1차 기준으로 사용
- SQL 고득점 Kit의 JOIN·GROUP BY·서브쿼리·윈도 함수 문제를 직접 풀이
- Java 문법이 익숙해지면 동일 문제 일부만 Java로 재풀이

### 3순위 — 적용형 CS 구술

- 자료구조 이름 전에 필요한 연산과 제약을 먼저 말한다.
- TCP의 전달 보장과 DB transaction의 원자성을 구분한다.
- Java collection, process/thread, lock·deadlock, HTTP, index, transaction isolation을 주문 시나리오로 설명한다.
- 주 1회 10분 기술면접 녹음과 백지 구현으로 검증한다.

### 후순위 — 영어와 자격증

TOEIC Speaking IH 또는 OPIc IM3~IH, 정보처리기사와 SQLD는 서류 보완 목표로 유효하다. 다만 프로젝트·코딩테스트 주간 루틴을 중단시키지 않는 범위에서 준비한다. TOEIC 730을 먼저 900으로 만드는 것보다 Java·SQL 프로젝트를 작동시키는 편이 현재 합격 확률에 더 큰 영향을 준다.

## 8주 후 지원 판정

다음 중 6개 이상을 만족하면 체험형 인턴 지원을 적극 확대한다.

- [ ] Java 주문 API를 새 환경에서 실행한다.
- [ ] 핵심 흐름을 10분 동안 자료 없이 설명한다.
- [ ] 실패·경계·동시성 테스트가 있다.
- [ ] JOIN·집계·서브쿼리를 직접 작성한다.
- [ ] 알고리즘 3+SQL 1 모의시험에서 두 번 연속 3솔 이상이다.
- [ ] 자료구조 선택과 복잡도를 연산 요구에서 설명한다.
- [ ] 트랜잭션·멱등성·TCP의 역할을 구분한다.
- [ ] 프로젝트 README에 본인 판단과 AI 기여 경계가 있다.
- [ ] 금융사 한 곳의 실제 서비스·배치·고객 문제와 프로젝트를 연결한다.

> [!note] Bias Check
> 공개 합격 후기는 강한 합격자가 글을 남기는 편향이 있고 회사별 공식 합격 커트라인은 공개되지 않는다. 사용자의 Java·SQL 실력도 아직 직접 진단하지 않았으므로 현재 평가는 자기보고와 면접 복기 기준이다. 2주 뒤 작동 코드와 모의시험 결과로 다시 판정한다.

# NICE 장학금 자기소개서 2차 초안

## 변경 방향

- 1번: `질문 → 축적 → 실험 → 다음 행동 수정`의 인과관계를 먼저 선언하고 Gemini Gem, LLM Wiki, Upbit·Threads 사례를 하나의 반복 과정으로 연결
- 2번: 학기당 대표 결과물을 하나로 고정하고 모든 지출을 2026-2 Threads 분석 보고서와 2027-1 Upbit 주문 장애 분석 결과물에 각각 연결
- 3번: 큐의 시니어 화면 안내 기능, 노인 사용자의 유료 이용 거부 판단, 개인 무료+B2B CPS 전환, 경남권 대상·U300+ 전국 400팀 선정, Google Play 출시 후 검증을 연결
- 4번: Python·Pandas 직접 정제, 초기 형식 채택과 사후 재분석, 중앙 참여율 1.01%→0.37%, 교란요인과 후속 비교 실험을 포함

## 1번 — 성장 스토리와 세 가지 키워드

공백·줄바꿈 포함 461자 / 500자 이내.

지난 3년간의 저를 나타내는 세 키워드는 질문·축적·실험입니다. 시행착오를 거치며 질문으로 문제를 쪼개고, 답을 축적한 뒤, 그 근거로 가설을 실험해 다음 행동을 바꾸는 사람으로 성장했습니다. 2025년 1학기 평점이 3.42로 낮아지자 공부법을 점검했습니다. 2학기부터 코딩테스트 알고리즘을 공부할 때 Gemini Gem을 단계별 힌트 튜터로 설정하고, 모르는 부분을 이해할 때까지 질문하며 전체 구조에서 세부 원리로 내려가는 탑다운 방식으로 공부했습니다. 2026년 1학기 평점을 4.10으로 올리고, 같은 학기 LLM Wiki를 만들어 글·영상·프로젝트와 아이디어를 에이전트로 연결해 축적했습니다. Threads에서는 반응 데이터를 축적해 다음 글 형식을 실험했고, 2학기에는 Wiki 기록을 꺼내 Upbit 주문 추적 프로젝트를 시작했습니다. 저는 질문을 지식으로 남기고, 지식을 실험으로 검증하며 성장하고 있습니다.

## 2번 — 꿈, 목표, 실천 계획과 장학금 활용

공백·줄바꿈 포함 786자 / 1,000자 이내.

제 꿈은 금융 데이터를 분석해 고객·시장·시스템의 의사결정을 개선하고, 분석 결과를 실제 금융 서비스에 구현하는 금융 IT 인재가 되는 것입니다. Threads 반응 데이터를 다음 글에 반영하며 분석의 필요성을 느꼈습니다. 현재 CSV·SQL 기초 집계는 가능하지만 통계적 검정과 실험 설계는 부족합니다.

2026년 2학기에는 직접 수행한 Threads 분석을 NICE 교육에서 배운 데이터 정제·비교 방법으로 고도화하겠습니다. 형식·주제별 차이와 한계를 담은 재현 코드·차트·보고서를 12월까지 완성하겠습니다. 예상 배분은 200만 원 중 인프런 Python·Pandas·SQL 강의 2개 28만 원, AWS EC2·RDS·S3 3개월 30만 원, 전문가 멘토링 4회 32만 원, 수집·시각화 도구와 대시보드·보고서 제작 50만 원, 3개월 교통·식비 60만 원에 사용하겠습니다.

2027년 1학기에는 현재 진행 중인 Upbit 주문 추적 프로젝트를 금융 데이터 분석 결과물로 완성하겠습니다. 공개 호가·체결 데이터를 수집하고 모의 주문 환경에 다섯 가지 장애를 각 10회씩 주입해 진단 정확도와 처리시간을 비교한 뒤, 파이프라인·대시보드·최종 보고서를 6월까지 공개하겠습니다. 예상 배분은 300만 원 중 인프런 금융 데이터 분석·백테스트 강의 2개 28만 원, AWS EC2·RDS·CloudWatch 3개월 45만 원, 장애·부하 실험 환경 47만 원, 멘토링 4회 40만 원, 사용자 검증 20명 40만 원, 대시보드·배포·포트폴리오 40만 원, 3개월 교통·식비 60만 원에 사용하겠습니다.

## 3번 — 예상하지 못한 어려움과 극복 경험

공백·줄바꿈 포함 471자 / 500자 이내.

‘큐’는 시니어가 디지털 서비스를 이용할 때 화면 위에서 실시간으로 길을 안내하는 오버레이 비서 앱입니다. 저는 팀원 4명과 함께 ‘모두의 창업’에 팀장으로 참가했습니다. 탈락 후 제품개발·초기 판로·지속 가능한 매출계획이 부족하다는 심사의견을 받았습니다. 팀장으로서 “내가 실제 노인이어도 돈을 내고 사용할까?”라고 물었고, 팀원들과 ‘아니오’라고 결론 내렸습니다. 효과를 경험하기 전 결제를 요구하는 것이 진입장벽이라고 판단해 개인은 무료로 이용하고, 제휴 상품 구매가 성사되면 기업으로부터 수수료(CPS)를 받는 구조로 바꿨습니다. 제품개발 단계와 제휴 경로도 보완해 6월 16일 경남권 대학생 창업동아리 심화교육에서 대상을 받고 U300+ 전국 400팀에 선정됐습니다. 아이디어를 방어하기보다 사용자 입장에서 반박해야 함을 배웠습니다. 현재 Google Play 심사 중이며, 출시 후 이용·구매전환 데이터로 수익모델을 검증하겠습니다.

## 4번 — 데이터 기반 의사 결정의 중요성

공백·줄바꿈 포함 461자 / 500자 이내.

데이터 기반 의사결정이 중요한 이유는 직관에서 출발한 가설을 검증하고, 결과에 따라 다음 행동을 수정할 수 있기 때문입니다. Threads 자동화 워크플로를 개발하며 ‘나쁜 요청과 좋은 요청을 대비하면 이목을 끌 것이다’라는 가설을 세웠습니다. 초기 좋아요·재게시 반응이 반복되자 이 형식을 다음 글에 적용했습니다. 이후 52개 게시물 원자료를 직접 Python·Pandas로 정제하고, 72시간 수집을 완료한 50개를 비교했습니다. 같은 구조 32개의 중앙 참여율이 초기 1.01%에서 후기 0.37%로 낮아지자 기존 결론을 고집하지 않고 형식 피로를 새 가설로 세웠습니다. 다만 주제·게시시간 차이가 있어 원인을 단정하지 않고, 동일 조건에서 기존 형식과 새 형식을 비교하는 후속 실험을 설계했습니다. 따라서 데이터는 결정을 정당화하는 숫자가 아니라, 가설의 한계를 드러내 다음 행동을 선택하게 하는 근거라고 생각합니다.

## 5번 — 데이터 관련 교육·수행 경험

공백·줄바꿈 포함 430자 / 500자 이내.

현재 데이터 분석 자격증·관련 수상은 없습니다. 경상국립대 데이터베이스PBL(A0)을 이수했습니다. 학부연구에서 AI가 생성한 JavaParser 결과를 검토하던 중 실제 src/test/java 파일은 153개인데 test 포함 경로가 171개로 집계된 이상을 발견했습니다. AI에 분류 기준 재검토를 요청해 소스 파일 18개가 테스트로 잘못 포함됐고, src/test/java 중심 분류가 필요함을 확인했습니다. 이 경험으로 자동 생성된 결과도 데이터 정의를 확인한 뒤 해석해야 한다는 것을 배웠습니다. 현재 Python·Pandas로 원자료를 정제하고 기초 비교하는 것은 가능하지만, 통계적 검정과 금융 데이터 분석 역량은 부족합니다. NICE 교육에서 알고리즘 공부에 사용해 온 Python을 실제 금융 데이터 처리로 확장하고 금융 백엔드 개발에 연결하겠습니다.

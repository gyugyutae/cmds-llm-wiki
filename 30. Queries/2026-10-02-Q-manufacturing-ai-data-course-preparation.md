# 제조 AI 데이터 분석 교육 사전 준비

## 질문과 사용자 맥락

사용자가 제공한 교육과정 이미지의 내용을 설명하고, 교육 전에 무엇을 공부하면 좋은지 현재 학습·진로 맥락에 맞춰 우선순위를 정했다.

확인된 맥락은 Python 사용 경험, Java를 새 주언어로 익히는 중이라는 점, 금융 백엔드와 금융 데이터 분석에 모두 관심이 있다는 점이다. 기존 기록은 Python/Pandas 데이터 분석 역량을 보완 과제로 잡고 있지만, 현재 Pandas 숙련도를 보여 주는 직접 평가 기록은 없다. 따라서 아래 준비 계획은 초중급이라고 단정하지 않고, 데이터 분석 라이브러리를 빠르게 다뤄보는 첫 준비로 설계한다.

## 이미지 속 과정 요약

이미지에 표시된 시간은 1일차 8시간, 2일차 8시간으로 총 16시간이다.

| 일정 | 모듈 | 실제로 하게 될 일 |
|---|---|---|
| 1일차 1H | 우주항공 제조 AI의 이해 | 제조 현장에서 AI를 어디에 쓰는지 사례를 보고, 생산·검사 데이터를 이용해 무엇을 예측할 수 있는지 이해한다. |
| 1일차 1H | 제조 데이터 분석 준비 | Python과 VS Code 분석 환경을 구성하고 주요 데이터 분석 라이브러리를 설치한다. |
| 1일차 1H | 제조 데이터 분석 기초 | 제조 데이터를 살펴보고, 표 형태 데이터와 행·열 구조를 이해하며 실습 데이터를 준비한다. |
| 1일차 3H | 제조 데이터 전처리 | 생성형 AI의 도움을 받아 코드를 작성하고, 결측치·이상치를 처리하며, 범주형 값을 숫자로 바꾸고, 학습·검증·테스트 데이터를 나눈다. |
| 1일차 2H | 제조 데이터 시각화 | 분포를 확인하고 히스토그램·산점도·히트맵으로 데이터를 탐색한다. |
| 2일차 3H | 머신러닝 예측과 분류 | 예측·분류 모델을 만들고 성능을 평가한다. 불량 예측과 설비 이상 예측도 실습한다. |
| 2일차 5H | 팀(개별) 프로젝트 | 제조 데이터를 분석하고 머신러닝 또는 딥러닝 모델을 적용해 결과를 해석하고 보고서를 작성한다. |

## 과정에서 익힐 핵심 개념

- **회귀 예측**: 온도·압력·진동 같은 입력으로 수치 결과나 남은 수명 등을 추정한다.
- **분류**: 제품이 정상인지 불량인지, 설비가 정상인지 이상 상태인지를 범주로 나눈다.
- **전처리**: 비어 있거나 잘못된 값을 다루고, 숫자가 아닌 항목을 모델이 쓸 수 있는 형태로 바꾼다.
- **학습·검증·테스트 분리**: 모델을 맞추는 자료, 설정을 고르는 자료, 마지막 성능을 확인하는 자료를 나눈다.
- **시각화**: 값의 범위와 분포, 변수 사이의 관계, 이상한 패턴을 그래프로 점검한다.
- **모델 평가**: 정확도 하나만 보지 않고 불량을 놓친 비용과 정상 제품을 불량으로 잡는 비용을 구분한다.

과정 소개만으로는 사용 라이브러리, 실제 데이터셋, 딥러닝 모델 종류, 프로젝트 평가 기준이 확인되지 않는다. 특히 16시간에 머신러닝과 딥러닝 모두를 깊게 배우기보다, 기본 흐름을 실습하고 결과를 해석하는 입문 과정으로 기대하는 편이 현실적이다.

## 지금 우선할 사전 공부

### 1순위: Pandas로 표 데이터를 읽고 다루기

이 과정은 Python 문법 자체보다 데이터를 불러와 정리하고 모델 입력으로 만드는 시간이 길다. 아래 작업을 직접 할 수 있으면 실습 진입이 편해진다.

- CSV를 `DataFrame`으로 읽기
- 행·열 선택, 조건 필터링, 정렬
- `isna`, `fillna`, `dropna`로 결측값 확인·처리
- `groupby`로 품목·설비별 요약
- `value_counts`, `describe`, `info`로 데이터 점검
- 중복 행과 데이터 타입 확인

### 2순위: 기초 시각화와 통계 감각

평균만 비교하면 데이터의 불균형이나 이상값을 놓칠 수 있다. 평균과 중앙값의 차이, 표준편차가 나타내는 퍼짐, 히스토그램에서 보는 분포, 산점도에서 보는 관계를 익힌다. 그래프를 그린 뒤 `무엇이 보이고 무엇까지는 결론 낼 수 없는지` 한두 문장으로 적는 연습이 유용하다.

### 3순위: 분류 모델 평가

불량 예측에서는 전체 정확도가 높아도 실제 불량품을 많이 놓칠 수 있다. 다음을 구분해 둔다.

- **Accuracy**: 전체 중 맞힌 비율
- **Precision**: 불량이라고 판정한 것 중 실제 불량인 비율
- **Recall**: 실제 불량 중 모델이 찾아낸 비율
- **Confusion matrix**: 정상/불량 각각을 맞히거나 틀린 수
- **Train/test split**: 학습에 쓴 행을 최종 평가에 다시 쓰지 않는 이유
- **Data leakage**: 미래 정보나 정답 정보를 전처리·학습 과정에서 미리 사용해 평가가 부풀려지는 문제

### 4순위: 제조 문제를 데이터 문제로 바꾸기

예를 들어 센서값과 검사 결과가 있다면 `이전 생산 조건으로 다음 제품의 불량 여부를 예측한다`처럼 입력, 정답(label), 예측 시점을 분리한다. 같은 제품의 측정값이 학습과 테스트 양쪽에 섞이지 않는지, 불량 비율이 정상보다 매우 낮지는 않은지 점검하는 습관이 중요하다.

## 권장 사전 학습안: 4회, 회당 약 45~60분

1. **데이터 읽기**: CSV를 읽고 `shape`, `head`, `info`, `describe`로 구조를 설명한다.
2. **정리하기**: 결측치·중복·범주형 열을 찾고, 품목이나 설비별 건수를 집계한다.
3. **그려보기**: 수치 열의 분포와 변수 관계를 그래프로 확인하고 발견한 점을 적는다.
4. **간단한 분류**: 학습·테스트를 분리해 기본 분류 모델 하나를 실행하고 Accuracy, Precision, Recall, 혼동행렬을 해석한다.

실습 목표는 코드를 외우는 것이 아니라, 데이터가 어떤 모양이고 어떤 결정을 내려야 하는지 설명하는 것이다. 기존 학습 원칙과 맞춰 생성형 AI가 만든 코드는 그대로 받아들이기보다, 각 처리 단계의 입력·출력과 선택 이유를 확인한다.

## 우선순위가 낮은 준비

- 딥러닝 수식이나 신경망 구조를 미리 깊게 공부하기
- 통계학 전 범위를 훑고 난 뒤에야 실습 시작하기
- GPU 환경이나 복잡한 가상환경을 미리 꾸미는 데 많은 시간을 쓰기
- 모델 이름만 많이 외우기

과정에서 환경 구성과 라이브러리 설치를 다루므로, 사전 준비 시간은 Pandas와 평가 개념에 쓰는 편이 낫다. 다만 교육 안내에서 사전 설치를 요구한다면 그 안내를 우선한다.

## 현재 커리어 학습과의 연결

이 교육은 현재 Java·Spring 금융 백엔드 학습을 대체하기보다, Python을 분석·자동화에 활용한다는 기존 방향에 보완 경험을 더한다. 금융 데이터 분석 관심과도 이어진다. 수료 후에는 제조 예제를 금융 데이터로 그대로 과장해 연결하기보다, CSV 정제·분류 지표 선택·불균형 데이터 해석 같은 공통 분석 과정을 한 번 다시 적용해 보는 것이 좋은 후속 연습이다.

강의 수료만으로 데이터 분석 역량이나 제조 AI 전문성을 주장하기는 어렵다. 결과물로 남길 때는 사용 데이터, 정제 기준, 예측 시점, 평가 지표, 모델이 놓친 사례를 기록한다.

## 자기 점검 질문

1. CSV를 읽은 뒤 행 수, 열 수, 자료형, 결측값 수를 어떻게 확인할 것인가?
2. 정상 99개, 불량 1개를 전부 정상이라고 예측한 모델의 Accuracy는 얼마이며, 왜 좋은 불량 예측기라고 할 수 없는가?
3. 같은 제품의 반복 측정 행을 무작위로 나눌 때 학습과 테스트에 같은 제품의 정보가 섞일 수 있는 이유는 무엇인가?

# 넥토리얼 지원동기와 게임 답변

## 핵심 포지셔닝

> 게임 개발 프로젝트와 C++·C# 실전 숙련도는 아직 부족하지만, 넥슨 게임에서 받은 오래 남는 경험을 다른 이용자에게 돌려주고 싶다는 동기가 있다. 학교에서 접한 C와 자료구조를 출발점으로, AI를 정답 생성기가 아닌 개인 과외 선생처럼 사용하며 모르는 부분을 작게 찾아 구현하고 검증하는 학습 방식을 갖고 있다.

약점을 AI 이야기로 덮지 않는다. `게임을 오래 플레이한 경험`과 `게임을 개발한 경험`은 구분하고, 빠른 학습력을 주장할 때는 반드시 자물쇠와 열쇠 문제처럼 막힌 지점·질문·직접 적용·결과가 이어지는 사례를 붙인다.

## 1. 왜 게임 프로그래머가 되고 싶은가

### 면접 답변

> 초등학생 때 추운 겨울이면 형제들과 이불 속에서 귤을 먹으며 메이플스토리를 하곤 했습니다. 시간이 많이 지났지만 당시의 맵과 몬스터, 캐릭터와 배경음악이 아직도 떠오를 만큼 좋은 기억으로 남아 있습니다. 저는 게임이 한때의 재미를 넘어 사람의 어린 시절과 관계, 감정을 오래 보존할 수 있다는 것을 그 경험을 통해 알게 됐습니다. 이제는 제가 게임에서 받았던 꿈같은 기억을 다른 이용자에게도 돌려주고 싶어 게임 프로그래머를 목표로 하게 됐습니다. 단순히 추억을 말하는 데서 그치지 않고, 이용자가 안심하고 오래 머물 수 있는 시스템을 만드는 개발자로 성장하고 싶습니다.

### 답변 구조

`구체적인 장면 → 게임이 내게 준 가치 → 개발자가 되고 싶은 이유 → 만들고 싶은 이용자 경험`

감정을 살리되 “게임이 좋아서 지원했다”로 끝내지 않는다. 마지막에는 반드시 프로그래머로서 만들고 싶은 경험으로 연결한다.

## 2. 왜 넥슨이고 왜 넥토리얼인가

### 면접 답변

> 메이플스토리뿐 아니라 카트라이더와 던전앤파이터를 초등학생 때부터 플레이했고, 지금도 FC 온라인을 즐기고 있습니다. 넥슨의 게임은 제게 새로 알게 된 회사의 제품이 아니라 성장 과정에서 오랫동안 함께한 익숙한 세계입니다. 그래서 이용자로서 느꼈던 즐거움과 아쉬움을 개발자의 질문으로 바꿔 보고 싶었습니다. 다만 제 경험이 모든 이용자를 대표한다고 생각하지는 않습니다. 제가 느낀 문제를 가설로 세우고 실제 이용자 반응과 행동 데이터를 통해 확인하는 개발자가 되고 싶습니다. 게임 개발 경험과 C++ 실전 역량이 부족한 현재의 저에게 넥토리얼은 현업의 기준으로 기본기를 배우고, 제가 가진 문제 정의와 학습 방식을 게임 개발 역량으로 전환할 수 있는 기회라고 생각해 지원했습니다.

//기본기는 지금 c 언어가 있는데 기본기를 실전에서 사용해보면서 더 현업능력을 넥토리얼 인턴기간동안 향상시켜보고싶다 이렇게 말하고싶다

### 과장하지 않을 경계

- “넥슨 게임의 문제와 이용자 요구를 누구보다 잘 안다”라고 말하지 않는다.
- 오래 플레이한 경험은 `관찰의 출발점`이지 전체 이용자 요구의 증거가 아니다.
- 넥토리얼에서 만든 결과가 곧바로 라이브 서비스에 배포된다고 단정하지 않는다.
- “대한민국 게임 산업에 기여하겠다”보다 먼저 어떤 기본기를 배우고 어떤 이용자 경험을 만들지 설명한다.

## 3. 게임 포트폴리오와 C++·C# 역량이 부족한데 왜 지원했는가

### 면접 답변

> 게임 프로젝트가 없고 C++·C# 실전 숙련도가 낮다는 점은 분명한 약점입니다. AI를 잘 활용한다는 말만으로 이 약점이 없어지지는 않는다고 생각합니다. 다만 학교 자료구조 수업에서 C로 포인터, 스택, 큐와 원형 큐를 구현하며 기초를 접했고, 이후 Python으로 덱, BFS·DFS, 그리디, 해시와 정렬 문제를 추가로 공부했습니다. 문제를 풀기 전 입력 크기를 보고 어떤 시간복잡도가 필요한지 먼저 생각하는 습관도 들였습니다. 저는 새로운 언어나 도구를 배울 때 전체 목표에서 현재 모르는 지점을 찾고, AI에는 정답 대신 사고 순서와 힌트를 요청한 뒤 제가 직접 구현하고 결과를 확인합니다. 아직 준비된 게임 개발자라고 주장할 수는 없지만, 부족한 범위를 정확히 알고 작은 구현과 검증으로 빠르게 줄여 나가는 학습 방식은 보여드릴 수 있습니다.

### 이 답변에서 지켜야 할 사실 경계

- 데이터베이스·네트워크·운영체제 수업을 들은 것과 해당 기초가 탄탄한 것은 다르다.
- 현재 이해도가 낮다면 “수업에서 접했으며 다시 보완 중”이라고 답한다.
- “언어만 다르고 본질은 모두 같다”보다 “자료구조와 문제 분해 지식은 전이되지만, C++의 메모리·객체 수명과 게임 엔진은 별도로 학습해야 한다”고 말한다.
- 학습 속도는 형용사가 아니라 `막힘 → 질문 → 직접 적용 → 검증` 사례로 증명한다.

## 4. AI를 활용해 빠르게 학습한 사례

### 면접 답변

> 프로그래머스의 자물쇠와 열쇠 문제를 풀 때 열쇠를 회전시키는 부분에서 막혔습니다. 저는 Gemini Gem을 정답을 바로 주지 않고, 문제를 해결하는 사고 순서와 단계별 힌트만 주는 개인 과외 선생처럼 설정해 사용했습니다. 질문을 통해 Python에서는 행렬 회전을 리스트 컴프리헨션으로 간결하게 표현할 수 있다는 점을 알게 됐고, 예시를 그대로 제출한 것이 아니라 제 코드의 보드 구조와 경계 처리에 맞게 직접 적용해 문제를 통과했습니다. 이 경험 이후 AI를 코드를 대신 작성하는 도구보다, 전체 문제에서 제가 모르는 지점을 찾아 하나씩 지워 가는 학습 도구로 활용하고 있습니다.

### 예상 꼬리질문

**Q. 이것도 결국 AI가 풀이를 알려준 것 아닌가요?**

> 회전 아이디어와 Python 표현법에 대한 힌트는 AI의 도움을 받았습니다. 제가 직접 한 부분은 그 표현을 제 자료구조에 맞게 적용하고, 회전한 열쇠를 보드의 여러 위치에 대입하면서 경계와 일치 조건을 확인한 것입니다. 다만 지금 백지에서 다시 구현하지 못한다면 완전히 제 것으로 만들었다고 말할 수 없기 때문에, 면접 전에는 회전식과 전체 풀이를 AI 없이 다시 작성해 확인하겠습니다.

**Q. 탑다운 학습이란 무엇인가요?**

> 먼저 해결하려는 전체 목표와 입출력을 파악한 뒤, 현재 해결을 막는 하위 문제를 찾고 그 부분만 학습해 다시 전체 문제에 적용하는 방식입니다. 자물쇠와 열쇠 문제에서는 전체 탐색 구조보다 회전 구현이 현재 막힘이라고 판단해 그 부분을 질문하고 적용했습니다.

**Q. 시간복잡도는 어떻게 판단했나요?**

> 입력 크기와 반복문의 중첩 정도를 보고 O(N²), O(N log N) 가운데 현실적으로 가능한 접근을 먼저 구상합니다. ‘Python은 1초에 항상 1억 번 연산한다’는 식의 고정 기준은 실행 환경과 연산 종류에 따라 크게 달라질 수 있으므로 면접에서는 단정하지 않습니다. 대략적인 연산량은 접근을 거르는 참고값으로만 사용하고 실제 제한과 알고리즘 복잡도를 함께 봅니다.

## 5. 이용자의 냉정한 피드백이 왜 매력적인가

### 면접 답변

> 게임 개발의 매력은 제가 만든 시스템과 콘텐츠가 실제로 재미있는지 이용자가 빠르고 솔직하게 반응한다는 점입니다. 반응이 차갑거나 때로는 개발자에게 아플 수 있지만, 게임을 진지하게 즐기는 이용자의 의견은 제가 무엇을 놓쳤는지 발견할 수 있는 중요한 신호라고 생각합니다. Threads 자동화에서도 처음 만든 형식의 반응이 낮자 문제 제시와 해결 순서를 바꾸고 실제 반응 변화를 확인했습니다. 게임에서도 피드백을 방어적으로 받아들이기보다 개선 가설로 전환하고 싶습니다. 다만 목소리가 큰 일부 의견을 전체 이용자의 요구로 단정하지 않고, 행동 데이터와 다양한 이용자 맥락을 함께 보며 판단하겠습니다.

## 6. 메이플스토리에서 어떤 시스템을 만들고 싶은가

### 현재 답변

> 아직 특정 시스템 하나를 충분한 근거를 가지고 정하지는 못했습니다. 지원서에서는 어린 시절 아이템과 메소를 거래했던 기억에서 출발해, 연결이 끊기거나 요청이 중복돼도 재화와 아이템이 정확히 반영되는 거래 시스템에 관심이 있다고 작성했습니다. 현재로서는 이 영역이 가장 구체적인 후보입니다. 다만 실제 개발 관점의 문제와 이용자 요구를 더 조사한 뒤, 왜 그 시스템이어야 하는지까지 설명할 수 있도록 정리하겠습니다.

없는 답을 급하게 꾸미지 않는다. 다음 단계에서는 `기억에 남은 실제 불편 → 누구의 문제인가 → 현재 시스템 확인 → 개선 가설 → 기술적으로 필요한 것`을 조사해 한 시스템을 선택한다.

## 7. 통합 90초 답변

> 초등학생 때 추운 겨울이면 형제들과 이불 속에서 귤을 먹으며 메이플스토리를 했습니다. 당시의 맵과 몬스터, 배경음악이 지금도 떠오를 만큼 넥슨 게임은 제 성장 과정에 오래 남아 있습니다. 저는 제가 받았던 그런 좋은 기억을 다른 이용자에게도 돌려주는 게임 프로그래머가 되고 싶습니다. 게임 프로젝트가 없고 C++·C# 실전 숙련도가 부족하다는 점은 분명히 알고 있습니다. 대신 학교에서 C로 포인터와 스택, 큐를 접한 뒤 Python으로 자료구조와 알고리즘 학습을 이어 왔고, AI를 정답 생성기가 아니라 모르는 지점을 찾는 개인 과외 선생처럼 활용해 왔습니다. 자물쇠와 열쇠 문제에서도 회전 구현에서 막히자 사고 힌트를 받아 제 코드에 직접 적용하고 검증했습니다. 넥토리얼에서는 이 학습 방식을 게임 개발 기본기와 결합하고 싶습니다. 이용자로서 느낀 점을 정답으로 단정하지 않고, 실제 피드백과 데이터를 통해 더 오래 기억되는 경험을 만드는 개발자로 성장하겠습니다.

## 암기 키워드

`겨울·형제·귤·메이플스토리 → 오래 남는 경험 → 다른 이용자에게 환원 → 게임 개발 경험 부족 인정 → C 자료구조에서 Python 알고리즘으로 확장 → AI는 힌트 교사 → 직접 적용·검증 → 사용자 의견과 행동 데이터를 구분`

문장 전체를 외우기보다 위 키워드의 순서만 기억한다. 답변할 때 실제 기억과 현재 수준에 맞는 표현을 사용한다.

> Counter-argument: 정서적인 게임 경험과 AI를 활용한 알고리즘 학습 사례는 동기와 성장 가능성을 보여주지만, 게임 개발 구현력이나 C++ 숙련도를 대신 증명하지는 않는다.
> Data gap: Gemini Gem 설정과 자물쇠와 열쇠 재풀이 기록, C 자료구조 구현물, 알고리즘 풀이 이력, 실제 게임 시스템 분석은 이번 정리에서 독립 확인하지 않았다. 모두 사용자 자기보고에 기반한다.

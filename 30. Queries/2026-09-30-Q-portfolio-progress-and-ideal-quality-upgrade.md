## 두 영상에서 직접 가져올 기준

- 코딩웨일: 목표 시장 설정 → 합격 자료와 조언 수집 → 기준 분석 → 이상형 작성 → 현실 조정 → 외부 검토 → 구현.
- 생각등대: 제목 → 그림 → 문제 → 해결 과정 → 결과의 같은 순서를 약 네 블록에 반복. 문제는 약 3줄, 해결은 약 3~4줄로 핵심 판단을 보여주고, 자세한 과정은 기술 글로 연결한다. 그림을 본인이 설명할 수 있어야 하며 수치에는 측정 조건을 붙인다.

다음 항목은 이 기준을 금융 프로젝트에 적용하기 위한 Codex의 추가 제안이다. 영상 작성자가 아래 기술 항목을 모두 요구했다는 뜻은 아니다.

## 네 블록의 깊이를 높일 제안

| 원자성·복구 | 출금 후, 입금 후, 원장 기록 중의 실패와 commit 전후 실패 구분 | DB에 실제 변경이 발생한 지점에 실패를 주입하고 새 연결로 결과를 조회. 요청 실패와 거래 미반영이 항상 같은 상태가 아님을 다루고 commit 후 응답 유실은 멱등성 블록으로 연결 |

| 정산 대사 | 내부 원장과 독립적으로 만든 외부 합성 명세의 누락·중복·금액 차이, 배치 중단·재시작 | 기준일·마감·매칭 키·상태 규칙을 정하고 오류 표본의 탐지·오탐을 확인. 불일치 목록과 처리 근거를 남기며 검증 없이 잔액을 자동 수정하지 않음. 배치 재실행의 중복 부작용과 SQL 실행계획을 검증 |

네 블록의 제목은 지금은 목표 제목이다. 실제 발생하지 않은 오류나 비교하지 않은 대안을 성공 경험으로 쓰지 않는다. 기본 rollback 검증만으로도 학습 가치가 있지만, 상세 포트폴리오에서는 실패 조건·데이터 확인·설계 판단까지 보여줄 때 설명할 깊이가 생긴다.

## 추가할 문서와 완료 기준

1. **금융 업무 규칙 한 페이지**: 내부 계좌이체라는 경계, 허용·거절 상태, 금액 규칙, 완료 거래의 차변·대변 합, 음수 잔액 금지, 잔액과 원장의 일치 조건. 외부 정산 자료가 무엇을 나타내는지 명시한다. 실제 은행 간 청산을 구현했다고 표현하지 않는다.
2. **제출 형태의 이상형 초안**: 첫 페이지에 서비스·본인 역할·기간·기술·트래픽 한 줄과 대표 사례를 요약하고, 네 블록은 같은 서식으로 작성한다. 빈칸은 `[측정 후 기입]`으로 남긴다. 기준 문서와 실제 제출 문서를 연결한다.
3. **성능 검증 계획**: 데이터량, 계좌 수, 특정 계좌 집중도, 조회·이체 비율, 정상·피크·재시도 요청, 배치와 API 동시 실행을 정한다. 응답시간·오류·데이터 정확성의 통과 조건을 먼저 정한다. 정상 처리량과 업무상 거절·시스템 오류를 구분한다. 목표 서버 사양은 처음의 용량 가설이며 측정된 병목에 따라 수정한다.
4. **운영 복구 사례**: API 한 대 중단, 배치 중단 후 재시작, DB 백업 복원 등의 후보에서 실제로 검증한 사례를 선택한다. 장애 전후의 거래 누락·중복과 복구 시간, 복구 가능한 데이터 범위를 확인한다. Primary/Standby라는 이름만으로 무손실·무중단을 주장하지 않는다.
5. **한 문제를 깊게 다룬 기술 글**: 동시 이체의 정합성과 잠금 비용, 또는 응답 유실 뒤 중복 이체 방지처럼 하나의 질문을 깊게 다룬다. 실패한 접근·대안 비교·SQL·실험 재현·적용 한계를 포함한다. 글 하나에 모든 기술을 나열하지 않는다.
6. **근거와 외부 피드백 연결**: 각 핵심 문장에 commit·SQL·테스트·결과 원본 링크를 붙인다. 본인 결정과 AI 도움을 구체적으로 밝히고, 실제 협업 사례는 별도 PR·리뷰 기록으로 제시한다. 금융 업무와 백엔드 구현을 검토할 사람에게 같은 초안을 보여주고 변경 이유를 남긴다.

## 다음 논의에서 정할 것

정산 대사의 비교 대상이 아직 열려 있다. 이상형에는 **상대 기관이 보낸 정산 명세를 흉내 낸 독립적인 합성 파일**을 제안한다. 내부 원장과 같은 로직으로 복사해 만든 파일은 독립적인 오류 발견 근거가 약하므로, 정해진 업무 규칙에 따라 별도로 표본과 오류를 구성한다. 외부 연동 실적처럼 표현하지 않는다. 내부 잔액·원장 검증과 외부 명세 대사는 각각 목적을 명시한다. 최종 선택은 사용자의 논의 뒤 확정한다.

현재 다음 산출물로 가장 필요한 것은 금융 업무 규칙 한 페이지와 제출 형태의 네 블록 초안이다. 실제 구현에 앞서 현업 리뷰에서 문제의 가치와 증거 조건을 검토할 수 있게 한다. 구현은 기존 학습 흐름과 병행한다.

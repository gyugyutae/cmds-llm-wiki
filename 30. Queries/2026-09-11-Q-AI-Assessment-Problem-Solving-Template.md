# AI 활용 역량평가 문제 해결 템플릿

## 한 줄 원칙

> AI에게 동의를 구하지 말고, 내가 먼저 문제를 정의한 뒤 AI에게 누락·오류·반례를 찾게 하고 최종 판단은 내가 한다.

## 전체 루프

```text
정의 → 정렬 → 분해 → 선택 → 실행 → 검증 → 제출
```

## 0. 문제를 읽고 혼자 먼저 적기

AI에게 입력하기 전에 다음 다섯 가지를 찾는다.

| 항목 | 내가 적을 내용 |
|---|---|
| 목표 | 최종적으로 무엇을 만들어야 하는가? |
| 입력 | 주어진 데이터·코드·조건은 무엇인가? |
| 출력 | 어떤 형식과 내용으로 제출해야 하는가? |
| 제약 | 시간, 도구, 성능, 금지사항은 무엇인가? |
| 성공 기준 | 무엇을 확인하면 완료라고 판단할 수 있는가? |

## 1. 이해 정렬

### 기본 문장

> 내가 이해한 문제는 [문제 정의]이고, 최종 목표는 [목표]다.  
> 입력은 [입력], 출력은 [출력], 제약은 [제약]이며 성공 기준은 [기준]이라고 이해했다.  
> 내 해석에서 빠진 조건, 잘못 이해한 부분, 모호한 부분만 지적해 줘. 아직 해결책은 만들지 마.

### 좋은 확인 질문

- 내가 빠뜨린 조건은 무엇인가?
- 내 가정 중 문제에서 보장하지 않는 것은 무엇인가?
- 실패할 가능성이 큰 경계 조건은 무엇인가?
- 성공 여부를 어떤 테스트로 확인할 수 있는가?

### 피할 질문

- “내가 이해한 게 맞아?”
- “알아서 분석해 줘.”
- “정답을 만들어 줘.”

AI는 사용자의 해석이 틀려도 쉽게 동의할 수 있다. 동의가 아니라 누락과 반례를 요청한다.

## 2. AI 의견을 선택·거절·수정하기

> 네가 지적한 내용 중 [A]는 문제 조건과 일치하므로 반영하겠다.  
> [B]는 주어진 자료에서 확인할 수 없어 가정으로 분리하겠다.  
> [C]는 목표 범위를 벗어나므로 제외하겠다.  
> 이 결정을 기준으로 해결 단계를 다시 정리해 줘.

판단 근거는 반드시 문제 조건, 제공 데이터, 테스트 결과 중 하나에 둔다.

## 3. 작업 분해

> 전체 결과물을 바로 만들지 말고 작업을 3~5단계로 나눠 줘.  
> 각 단계마다 입력, 처리, 출력, 실패 조건, 검증 방법을 한 줄씩 제시해 줘.  
> 의존관계와 가장 위험한 단계를 표시해 줘.

## 4. 실행 순서 선택

AI가 제시한 순서를 그대로 따르지 않고 본인이 선택 이유를 말한다.

> [단계]가 실패하면 전체 결과가 무효가 될 가능성이 가장 크다고 판단했다.  
> 따라서 이 단계부터 가장 작은 예제로 검증하겠다.  
> 최소 입력과 예상 출력을 만들어 줘.

## 5. 작은 단위 실행

> 지금은 [선택한 단계]만 구현해 줘.  
> 입력은 [값], 기대 출력은 [값]이다.  
> 다른 단계는 수정하지 말고, 변경한 부분과 이유만 설명해 줘.

코드나 문서가 나오면 다음 단계로 바로 넘어가지 않고 실제 결과를 확인한다.

## 6. 반례와 검증

> 이 결과가 실패할 수 있는 정상·경계·오류 조건을 각각 찾아 줘.  
> 각 조건의 입력, 예상 결과, 검사 방법을 표로 만들어 줘.  
> 요구사항 중 아직 충족되지 않은 항목을 근거와 함께 표시해 줘.

### 검증 후 판단 문장

> 테스트 [A, B]는 통과했지만 [C]에서는 [실패]가 발생했다.  
> 원인은 [관찰 가능한 근거]라고 판단한다.  
> 전체를 다시 만들지 말고 해당 원인과 연결된 부분만 수정해 줘.

## 7. 최종 제출 전 점검

> 최초 요구사항을 체크리스트로 다시 만들고 현재 결과를 대조해 줘.  
> 각 항목을 충족, 부분 충족, 미충족으로 표시하고 근거를 제시해 줘.  
> 확인되지 않은 가정과 남은 위험을 분리해 줘.  
> 새로운 기능은 추가하지 마.

최종 판단은 AI의 “완료되었습니다”가 아니라 직접 확인한 실행 결과와 요구사항 대조로 내린다.

## 토큰 효율 규칙

목표는 최소 토큰이 아니라 의미 없는 왕복을 줄이는 것이다.

- 목표·입력·출력·제약·성공 기준을 한 번에 전달한다.
- 답변 형식을 표, 체크리스트, 3단계 계획처럼 제한한다.
- 이전 조건 전체를 반복하지 않고 변경된 조건만 전달한다.
- “다시 해 줘” 대신 실패 지점과 수정 범위를 지정한다.
- 전체 재생성보다 가장 작은 단계만 요청한다.
- 장황한 설명이 필요 없으면 “이유는 한 줄씩”이라고 제한한다.

토큰 사용량 자체가 공개된 직접 채점 기준인지는 확인되지 않았다. 효율성은 적은 토큰보다 적절한 정보로 정확한 결과를 얻는 과정으로 보여준다.

## 시험 중 기억할 6문장

1. 내가 이해한 문제는 X이고 목표는 Y다.
2. 입력·출력·제약·성공 기준은 A·B·C·D다.
3. 내 해석의 누락·오류·모호함만 지적해 줘.
4. 작업을 입력·출력·검증 기준이 있는 단계로 나눠 줘.
5. 나는 이 근거로 N단계부터 실행하겠다.
6. 결과의 반례와 미충족 요구사항을 검사해 줘.

## 초압축형

```text
문제: [내 해석]
목표: [최종 결과]
입력/출력: [A] → [B]
제약: [조건]
성공 기준: [검사 기준]

1. 내 해석의 누락·오류·모호함만 지적해 줘.
2. 작업을 입력·처리·출력·검증 기준으로 분해해 줘.
3. 가장 위험한 단계와 최소 검증 예시를 제시해 줘.
4. 결과가 나오면 반례와 미충족 요구사항을 검사해 줘.
```

## 실패 방지 체크

- [ ] AI에게 문제 전체를 바로 풀라고 하지 않았다.
- [ ] 내가 먼저 목표와 성공 기준을 정의했다.
- [ ] AI에게 동의가 아니라 누락·오류·반례를 요청했다.
- [ ] AI 제안 중 선택·제외한 내용과 이유를 밝혔다.
- [ ] 가장 위험한 부분을 작은 예제로 먼저 검증했다.
- [ ] 정상·경계·오류 조건을 확인했다.
- [ ] 전체 재생성 대신 실패 부분만 수정했다.
- [ ] 최종 요구사항과 실제 결과를 직접 대조했다.
- [ ] 확인되지 않은 가정을 사실처럼 제출하지 않았다.

# 한국 일반기업 백엔드 업계 비교

## 한 줄 결론

김규태에게 금융권 밖의 1차 확장 범위는 `대기업 IT서비스·제조/모빌리티 IT → 커머스·결제·물류 플랫폼 → Java 제품기업·SaaS`다. 네이버·쿠팡·당근 같은 상위 플랫폼은 보상과 기술 경험의 상단이 높지만 신입 경쟁이 강하다. 삼성SDS·LG CNS·SK AX·현대오토에버 같은 그룹 IT서비스사는 Java·SQL 기반 업무가 넓고 대규모 신입 진입면이 상대적으로 현실적이다. 중소 SI/SM은 진입면이 넓을 수 있지만 소속, 상주, 야근, 코드 소유권과 성장 경로의 편차를 반드시 확인해야 한다.

## 임금 데이터 경계

2026 State of Dev in South Korea 설문의 근무자 77명 중 보상 응답 기준 전체 중앙 구간은 세전 총보상 6천만~7천만 원, 0~3년차 19명은 4천만~5천만 원이었다. 그러나 영어권·외국인 개발자와 경력자가 섞인 작은 자가응답 표본이므로 한국 신입 전체 평균으로 일반화하지 않는다.

한국인공지능·소프트웨어산업협회의 2026년 적용 응용 SW 개발자 월평균임금은 7,754,124원이지만, 이는 SW사업 대가 산정용 인건비로 기본급뿐 아니라 상여·퇴직급여충당금·회사 부담 보험료를 포함한다. 개인이 받는 월급이나 신입 초봉으로 사용할 수 없다.

따라서 아래 임금은 금액 예측이 아니라 상대 경향이다. 실제 비교에서는 `기본연봉 + 고정상여 + 성과급 + 주식/RSU + 퇴직금 포함 여부 + 포괄임금 + 복지`를 같은 기준으로 환산한다.

`대표 기업`은 유형을 이해하기 위한 예시이며 현재 신입을 채용한다는 뜻은 아니다. 2026년 9월 네이버의 공개 채용 목록도 백엔드는 경력 수시채용이 중심이고, 상위 플랫폼의 신입 문은 특정 공채·인턴 시기에 집중된다.

## 유형별로 실제 얻는 경험

### 대형 플랫폼·커머스

- 장점: 대규모 트래픽, 실험·모니터링, 분산 시스템, 좋은 동료와 기술 브랜드
- 단점: 채용 난도가 높고 작은 기능만 담당할 수 있으며 서비스 장애와 성과 목표 부담
- 확인: 신입이 실제 배포하는가, 팀의 온콜 주기, 장애 회고 공개 범위, 조직개편 빈도

네이버 신입 Tech 공고는 백엔드를 데이터·비즈니스 로직·성능·보안을 책임지는 직무로 설명하고 여러 언어 중 하나로 코딩테스트를 허용했다. 당근 백엔드 공고는 JVM·Spring뿐 아니라 한 서비스를 오래 책임진 경험, 지표 측정, 사용자 가치와 방향 전환 판단을 요구한다. 이는 상위 제품기업이 단순 프레임워크 사용보다 운영 소유권을 중요하게 본다는 사례다.

### 대기업 IT서비스·제조 IT

- 장점: Java·SQL 수요가 넓고 대규모 업무 시스템, 글로벌 공장·그룹사 도메인 경험
- 단점: 고객사 요구와 납기가 기술 선택보다 앞설 수 있고 구축·운영·상주 비중이 큼
- 확인: 자사 개발인지 고객사 구축인지, 운영과 개발 비율, 협력사 관리가 주업무인지, 근무지 이동

현대오토에버 공고에는 Java/Spring API, SQL·NoSQL, Docker/Kubernetes, CI/CD뿐 아니라 생산계획·공장 시스템 개발과 운영이 함께 나타난다. 같은 회사 안에서도 AI 서비스 팀과 공장 운영 팀의 기술문화와 워라밸이 다를 수 있다는 예다.

### 스타트업·SaaS

- 장점: 요구사항부터 배포·운영까지 넓게 소유하고 빠르게 성장 가능
- 단점: 멘토 없이 기술부채만 떠안을 수 있고 자금·시장 상황에 따라 고용 안정성이 낮음
- 확인: 현금 보유기간, 매출·고객, 시니어 개발자 수, 테스트와 리뷰 시간, 스톡옵션 행사가·희석 조건

### SI/SM

- 장점: 신입 진입 기회, 다양한 산업 도메인, 요구사항·DB·운영 경험
- 단점: 코드를 직접 소유하지 못하거나 고객사 상주, 오래된 기술, 다단계 하도급에 놓일 수 있음
- 확인: 원청/하청 단계, 실제 소속과 근무지, 프로젝트 종료 뒤 배치, 야근수당, 코드리뷰·테스트·배포 권한

## 현업 개발자가 회사 선택에서 보는 핵심 요소

연봉과 워라밸만큼 아래 요소가 장기 몸값을 결정한다.

1. **팀과 멘토**: 신입 코드를 실제로 리뷰할 시니어가 있는가.
2. **제품 소유권**: 기능을 만들고 배포·지표·장애·개선까지 볼 수 있는가.
3. **개발과 운영의 비율**: 개발자인데 엑셀 보고·협력사 관리·문의 대응이 주업무는 아닌가.
4. **코드 품질 체계**: PR 리뷰, 자동 테스트, CI/CD, 모니터링, 장애 회고가 실제로 작동하는가.
5. **온콜과 야근**: 월 횟수, 새벽 호출, 대체휴무·수당, 배포 시간과 장애 책임 범위.
6. **기술부채**: 레거시가 있다는 사실보다 개선 시간과 권한이 있는지가 중요하다.
7. **성장 가능한 문제**: 트래픽 숫자보다 동시성·정합성·성능·장애 같은 어려운 문제를 직접 다루는가.
8. **평가와 보상**: 기본급·성과급·RSU, 평가 기준, 승진·연봉 조정 주기가 투명한가.
9. **사업 안정성**: 제품 매출, 투자금, 핵심 고객 의존도, 구조조정과 조직개편 이력.
10. **근무 조건**: 출근 일수, 통근시간, 휴가 사용, 포괄임금제, 수습기간과 계약 형태.

작은 2026 개발자 설문에서는 0~3년차보다 경력이 쌓일수록 보상이 커졌고, 근속연수뿐 아니라 고용주 유형에 따른 차이도 컸다. 원인으로 단정할 수는 없지만 `어느 기술을 쓰는가`만큼 `어떤 회사와 팀에서 어떤 책임을 갖는가`가 중요하다는 참고 근거다.

## 면접에서 확인할 질문

- 신입이 입사 후 3개월 동안 맡는 첫 업무는 무엇인가요?
- 최근 PR 하나가 리뷰부터 배포까지 가는 과정을 설명해주실 수 있나요?
- 팀의 자동 테스트 범위와 배포 빈도는 어느 정도인가요?
- 장애 대응은 몇 명이 어떤 주기로 맡고 보상·대체휴무는 어떻게 되나요?
- 신규 개발과 운영·유지보수 비율은 어느 정도인가요?
- 제가 들어갈 팀에 백엔드 시니어와 코드리뷰 담당자가 몇 명인가요?
- 고객사 상주나 근무지 변경 가능성이 있나요?
- 최근 1년간 팀에서 개선한 가장 큰 기술부채는 무엇인가요?
- 성과평가에서 개발자는 어떤 결과와 행동으로 평가받나요?

## 김규태에게 적용

금융 프로젝트를 버리고 일반기업용 쇼핑몰 프로젝트를 따로 만들 필요는 없다. [[2026-09-13-Q-java-bank-transfer-ledger-portfolio-design]]의 이체·원장 시스템은 커머스에서는 결제·주문 정합성, 제조 IT에서는 트랜잭션·운영 안정성, 플랫폼에서는 중복 요청·관측성·성능으로 번역할 수 있다.

지원 포트폴리오를 한 회사군으로 제한하지 말고 다음 세 묶음으로 운영한다.

1. 금융·결제: 은행, 증권, 카드, PG, 핀테크
2. 대기업 시스템: 삼성SDS, LG CNS, SK AX, 현대오토에버 등 IT서비스·제조 IT
3. Java 제품기업: 커머스, 물류, SaaS, 교육·헬스케어 플랫폼

첫 직장에서 최우선으로 볼 것은 최고 연봉이 아니라 `실제 Java 개발과 코드리뷰 → 직접 배포·운영 → 정합성·성능 문제 → 증거로 남길 결과`가 이어지는가다. 이 조건을 충족하면서 보상과 워라밸이 감당 가능한 회사를 선택한다.

## 근거 경계

기업 예시는 공개 채용 페이지와 2025~2026 채용 흔적을 기준으로 분류했다. 회사 전체의 문화·워라밸을 특정 공고 한 건으로 확정하지 않는다. 임금은 신입 백엔드만 분리한 업종별 대표 통계가 없어 상대 경향으로만 표시했으며, 실제 지원 시 공고·DART·현직자 인터뷰·처우 제안을 다시 확인한다.

## 재사용

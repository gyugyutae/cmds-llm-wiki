## Portfolio Spine

### 이상형 기준안 — 현실 조정은 다음 단계

**2026-10-11 취업 영상 묶음:** [[ideal 이력서와 포트폴리오 참고 영상 활용 지도]]에 자기소개 영상 누락 보완까지 관련 Clippings 24개(중복 통합 후 영상 22개)의 원문과 적용 위치를 연결했다. 신규 Raw Source 20개·기존 원문 2개를 활용한다. 목적은 현재 ideal 이력서·포트폴리오 개선이며 분량 결정은 이력서 2장·포트폴리오 5장으로 유지한다. 상세 사례 구조·문장 압축·가정과 측정·스펙 배치·설명과 피드백은 새 가이드로 재사용한다.

**2026-10-11 현재 편집 기준:** [[이력서는 프로젝트 포트폴리오는 문제 해결로 구성한다]]를 따른다. 이력서는 프로젝트 나열로 2장, 포트폴리오는 역량이 가장 잘 드러나는 문제 해결 경험으로 5장이다. 이력서 항목은 1~2줄, 프로젝트당 약 7줄로 압축한다. 아래 2026-10-06의 포트폴리오 2쪽 결정은 이전 기준이며, 기존 원고는 새 제출본의 재료로 보존한다. 이번 인제스트는 영상 URL·사용자 메모·첨부 화면을 수집한 것으로 영상 전체 자막은 미확보다.

2026-10-06 최신 기준은 [[2026-10-06-Q-two-page-financial-portfolio-k6-and-domain-rules]]와 [[2026-10-06-Q-portfolio-architecture-technical-article-and-target-profile]]다. 제출은 개인 1개 + 협업 1개를 2쪽 이내로 편집한다. 금융의 네 사례는 한 프로젝트의 상세 경험이다. k6·모의 기관으로 거래 대사와 복구를 검증하고, 지급망별 공식 근거와 자체 마감 정책을 구분한다. 전체 그림은 DB·기관 경계·명세·복구 경로를 표시한다. 대표 글은 응답 유실 거래의 확정과 대사를 깊게 설명한다. 협업은 금융 주제보다 본인 구현·리뷰·통합·실사용 증거를 우선한다. 공개 합격자의 수치는 합격선이 아니며 자격·어학 목표는 달성 전 경력으로 표시하지 않는다. 기존 여러 쪽 구성은 상세 기록이다.

[[2026-10-01-Q-financial-portfolio-integration-reconciliation-and-review]]는 별도 모의 기관 연동을 포함할 추천 범위, 대사 명세·마감 예시, 팀장 + 백엔드 모듈 책임, 실험·기여 증빙을 제시한다. 사용자는 팀장을 원하며 협업 주제는 아직 선택 전이다. 연구실 요청 자료는 2026-10-06 사용자 정정으로 제거했다.

[[2026-10-01-Q-ideal-portfolio-submission-draft]]는 소개·개인 프로젝트 개요·네 금융 문제 해결 블록·협업 개요와 사례 후보를 실제 문서 순서로 작성한 제작본이다. 모든 사례는 제목·그림·문제·해결·결과 순서이며 결과는 실측 전 빈칸이다. 개인 업무 경계와 합성 명세는 제안 상태, 협업 주제·사용자·팀과 마지막 페이지는 미정이다.

개인 프로젝트 하나와 협업 프로젝트 하나의 이상형, 한 프로젝트 안의 네 금융 해결 사례, 실행·측정·복구·대표 글로 구성한 최종 산출물은 [[2026-09-30-Q-financial-portfolio-deliverables-and-reference-review]]에서 검토한다. 협업 프로젝트는 기존 후보를 고르기 전에 이상형을 먼저 정하며, 마지막 페이지 영상 확인은 사용자 요청으로 다음에 진행한다.

2026-09-30 사용자는 기존 트래픽·초기 서버 사양을 기준으로 수용했고, Mac의 financial-lab이 최신 작업본이라고 확인했다. 현재 기획 진행과 추가 이상형 조건은 [[2026-09-30-Q-portfolio-progress-and-ideal-quality-upgrade]]에서 확인한다. 금융 업무 규칙과 제출 형태의 네 블록 초안을 다음 기획 산출물로 제안한다.

이상형 기준안은 [[2026-09-28-Q-ideal-financial-backend-portfolio]]에 정리했다. 사용자는 이체·원장을 중심 업무로, 정산/대사를 문제 해결 사례로 연결하는 방향을 선택했다. 이체 workload·피크 TPS·초기 인프라를 한 줄의 가정으로 추가했으며, 실측 전의 설계 초안이다. 생각등대의 반복 문제 해결 블록과 코딩웨일의 이상형 선설계 절차 적합성은 [[2026-09-28-Q-ideal-portfolio-fit-audit]]에서 점검했다. 현재 코드나 주당 학습 시간은 이상형 설계 경계로 삼지 않으며, 아래 프로젝트 spine은 현재 진행 기록으로 남긴다. 현실 조정은 이상형을 검토한 다음 단계다.

## Resume Positioning

현재 기본 포지셔닝:

> Codex를 적극 활용해 앱 개발, 자동화, 프로젝트 증거화를 수행하는 개발자 취업준비생. AI에 의존하는 개발자가 아니라 AI를 개발 역량의 증폭기로 활용하는 사람으로 성장하기 위해, 직접 판단한 부분과 AI가 도운 부분을 분리해 기록하고 검증한다.

백엔드 중심으로 다듬은 기본 포지셔닝:

> 금융 latency, 데이터 처리, Android 접근성, Codex 자동화 문제를 탐색해 온 개발자 취업준비생. Java를 새 주언어로 학습하고 Python을 분석·자동화에 활용하며, 현재 프로젝트 상당 부분이 AI 생성 코드에 의존했다는 한계를 공개하고 직접 설명·수정·재현 가능한 Java 백엔드 증거를 보강하고 있다.

이 문장은 아직 초안이다. 실제 이력서에는 지원 직무와 회사 유형에 맞춰 더 날카롭게 다듬는다.

### Overseas Entry-Level Route

해외 신입 지원은 선호 국가와 실제 진입 경로를 분리한다. 장기 선호는 미국 → 캐나다 → 유럽이지만, 2027년 8월 졸업예정을 기준으로 캐나다 IEC, 미국 J-1/WEST의 졸업 전후 12개월 창구, 독일 기회카드·신규 졸업자 EU Blue Card 요건을 각각 확인한다. 상위 직무 정체성은 `신뢰할 수 있는 데이터 시스템을 만드는 신입 소프트웨어 엔지니어`로 두고 Backend·QA Automation·Data 지원본을 분리한다. 월드잡 공개 이력서는 국가 중립형으로 유지하고 지원 공고마다 미국·캐나다·독일 버전을 별도로 사용한다. 상세 조사와 5축 100점 준비도 기준은 [[2026-09-18-Q-worldjob-overseas-entry-level-developer-resume-strategy]]를 따른다.

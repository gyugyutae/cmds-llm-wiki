# 채용공고와 기여 증거를 연결하는 지원동기

## 사용자가 원하는 지원동기

김규태는 회사·서비스 칭찬보다 “나를 뽑으면 이 팀에 어떤 도움을 줄 수 있는가”를 실제 경험으로 설명하고 싶다고 확인했다. 회사에 관심을 가진 이유와 팀의 문제, 본인 경험의 연결을 구체화한다.

## 작성 절차

1. 공고·공식 기술 자료에서 확인된 업무와 문제를 적는다.
2. 기술 목록에서 추정한 구조는 가설로 표시한다. Kafka·Spring Batch가 나열되었다고 내부 데이터 흐름을 확정하지 않는다.
3. 문제와 직접 대응되는 본인의 구현·판단·검증 자료를 고른다.
4. 신입으로 맡아 기여할 범위를 말하고 부족한 기술의 학습 근거를 붙인다.

## 세 문장 골격

> 귀 팀이 [공고에서 확인한 업무]를 맡는다는 점에 관심을 가졌습니다. 저는 [프로젝트]에서 [직접 수행한 일]을 하고 [실제 검증 자료]로 [결과와 한계]를 확인했습니다. 이 경험을 바탕으로 [구체 업무 범위]에 기여하면서 [미경험 영역]을 배우고 싶어 지원했습니다.

대괄호는 실제 자료로 채워야 한다. 사용자 기획 목표를 과거형 성과로 쓰지 않는다. “적응 기간 없이 즉시 기여”는 영상의 강한 표현이며 신입의 확정 약속으로 복제하지 않는다.

## 금융 백엔드에 연결할 후보

[[financial-lab]]의 직접 구현과 실패 후 잔액 유지 검증은 거래 규칙을 이해하려는 경험으로 연결할 수 있다. DB 원자성, 동시성, 실서비스 운영의 완성 증거는 별도 확보가 필요하다. 특정 회사·팀의 실제 공고가 들어오면 그 업무에 맞춰 문장을 작성한다.

> [!note] Bias Check
> Counter-argument: 지원동기의 비중은 회사·전형마다 다르며 기술 역량과 지원 자격도 함께 평가된다.
> Data gap: 현재 특정 금융회사 팀의 최신 공고와 목표 포트폴리오 문안은 제공되지 않았다.

## 2026-10-11 보강 — 자기소개 문항에도 적용

[[2026-10-11-YouTube-취준 이력서 10분만에 방향성 제대로 알려줌]] 1:38~2:44와 [[2026-10-11-YouTube-자기소개 5분만에 써드립니다. 그냥 가져가세요.]] 1:57~2:34는 공고 업무·기술과 본인 경험을 대응시키라고 조언한다. 공고의 기술 목록에서 주문/정산 데이터 흐름을 추정할 수는 있지만 회사의 실제 내부 구조라고 단정하지 않는다.

긴 자기소개 문항은 질문에 답하면서 주제별 문단으로 나누고, 문제→변화 또는 경험→기여가 보이는 소제목을 붙인다. 500자 단위·450자 본문/50자 제목은 [[2026-10-11-YouTube-자기소개 5분만에 써드립니다. 그냥 가져가세요.]] 0:30~1:22의 예시이며 실제 입력 제한·문항을 먼저 따른다. 예시 기술이나 사용하지 않은 경험을 끼워 맞추지 않는다.

[[2026-10-11-YouTube-개발자 취업 전략, 지금까지 듣지 못한 방법입니다]] 9:43~10:22의 회사 문제에 관한 대화와 [[2026-10-11-YouTube-다시 취준생 되면? 나 이 7가지는 무조건 함]] 0:00~1:19의 공고 적합성은 “확인한 업무→내 실제 증거→신입으로 기여할 범위”로 적용한다. 회사에 반드시 도움이 된다는 약속이나 면접 결과를 보장하지 않는다.

현재 수집 목적은 ideal 이력서·포트폴리오 개선이며 특정 회사의 실제 지원동기는 아직 작성하지 않았다. [[ideal 이력서와 포트폴리오 참고 영상 활용 지도]]와 연결한다.

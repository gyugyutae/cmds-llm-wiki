# 개발자 이력서 첫 페이지와 대표 증거

## 자막에서 추출한 작성 기준

생각등대는 신입/경력 상태를 상단에 명확히 쓰고, 대표 기술 글이나 증거를 직접 연결하며, 간결한 문서와 지원동기를 준비하라고 조언한다. AI 서대표의 사례는 공고의 우대사항과 사용자·도메인 고민을 구체적으로 읽었다는 신호를 강조한다.

## 김규태에게 적용하는 구성안

- 신입 지원, 2027년 8월 졸업 예정, 금융권 Java 백엔드 목표를 빠르게 식별하도록 배치한다.
- 소개 한두 문장에 실제 설명 가능한 문제와 경험을 적는다.
- [[채용공고와 기여 증거를 연결하는 지원동기]]를 회사별로 맞춘다. 지원 양식에 별도 칸이 있으면 그 지침을 따른다.
- 블로그 홈보다 가장 강한 문제 해결 글·코드·검증 자료에 직접 연결한다.
- 프로젝트는 문제 → 본인 판단 → 구현 범위 → 검증 → 결과·한계로 요약한다.

상단 증거는 [[financial-lab]]에서 직접 설명·수정 가능한 완료 부분부터 고른다. 목표 포트폴리오의 미래 성과를 넣지 않는다. 그림·색상 금지는 발표자 의견이므로 읽기 쉬운 구성과 제출 양식에 맞춰 판단한다.

> [!note] Bias Check
> Counter-argument: 첫 페이지 구성만으로 기술 심사·코딩테스트·면접을 대신할 수 없다.
> Data gap: 영상의 구성 방식이 금융권 신입 서류 합격률을 얼마나 높이는지 비교 자료는 없다.

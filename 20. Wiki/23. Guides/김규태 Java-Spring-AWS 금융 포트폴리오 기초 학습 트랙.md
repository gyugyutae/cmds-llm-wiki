# 김규태 Java-Spring-AWS 금융 포트폴리오 기초 학습 트랙

> [!important] 중심축
> 이 트랙은 금융 포트폴리오 프로젝트를 시작하기 전, Java·Spring Boot·AWS의 기초를 직접 설명하고 구현할 수 있게 만드는 준비 과정이다. 완독률보다 질문, 오개념, 직접 구현, 테스트와 재설명 기록을 우선한다.

## 병렬 교재의 역할

| 교재 | 주 역할 | 이 트랙에서 확인할 것 |
|---|---|---|
| 《스프링 부트 4 개발자 되기 + AI: 자바 편》, 신선영 | 현재 Java·Spring Boot 문법과 구조를 익히는 주 교재 | Java 문법, 객체지향, Spring 계층, DI, HTTP/API, JPA, 테스트를 자기 말로 설명하고 작은 코드로 재현하는가 |
| 《스프링 부트와 AWS로 혼자 구현하는 웹 서비스》 | 서비스 구성과 배포 흐름을 보는 병렬 실습서 | 예전 버전의 코드를 그대로 외우지 않고 현재 학습 내용과 차이를 구분하며 빌드·환경설정·DB·배포·운영 흐름을 이해하는가 |

두 책의 진도를 억지로 같은 장에 맞추지 않는다. 첫 책에서 개념을 배우고 두 번째 책에서 그 개념이 실제 서비스와 배포에 어떻게 쓰이는지 대조한다. 버전 차이로 생긴 오류는 실패가 아니라 `프레임워크 변화`, `설정 방식`, `의존성`, `배포 환경`을 구분하는 학습 자료로 남긴다.

## 앞으로 질문을 기록하는 방식

사용자가 Java·Spring Boot·AWS 학습 질문을 하면 기존 대화와 공부 노트를 함께 보고 다음 단위로 누적한다.

1. **학습 맥락**: 어느 책·장·예제에서 나온 질문인가.
2. **현재 이해**: 사용자가 이미 알고 있는 부분과 자기 말로 설명한 내용을 분리한다.
3. **막힌 지점**: 용어, 실행 흐름, 문법, 설계 이유, 오류 해석 중 어디서 막혔는지 기록한다.
4. **오개념 교정**: 틀린 답을 지우지 않고 `처음 생각 → 교정 근거 → 바뀐 이해`로 남긴다.
5. **직접 확인**: 최소 예제, 테스트, 로그, 디버거 또는 공식 문서로 확인한 결과를 남긴다.
6. **재시험 질문**: 정답을 본 직후가 아니라 다음 질문에서 다시 설명하거나 변형 문제를 풀게 한다.
7. **금융 연결**: 억지로 금융 용어를 붙이지 않고 주문·계좌·잔액·체결·정합성 문제와 실제 연결될 때만 기록한다.

## 약점 추적표

| 영역 | 약점으로 판정하는 신호 | 통과 증거 |
|---|---|---|
| Java 문법·실행 모델 | 문법은 읽지만 변수 수명, 참조, 예외, 컬렉션 동작을 설명하지 못함 | 빈 화면에서 작은 예제를 작성하고 실행 결과를 예측·수정함 |
| 객체지향 | 클래스만 나누고 책임, 상태, 불변식, 인터페이스 선택 이유가 없음 | 주문 상태 모델을 직접 설계하고 대안을 비교 설명함 |
| Spring Boot | 어노테이션을 외우지만 요청부터 DB까지 흐름을 추적하지 못함 | HTTP 요청이 controller-service-repository를 지나는 과정을 설명·디버깅함 |
| DB·JPA | 저장 성공만 확인하고 SQL, 트랜잭션, 제약조건, 동시성을 모름 | 생성 SQL을 확인하고 중복·롤백·동시 요청 테스트를 작성함 |
| 테스트 | 정상 동작 예제만 실행함 | 실패·경계·중복 요청을 JUnit으로 재현하고 수정 전후를 비교함 |
| AWS·배포 | 배포 명령을 복사하지만 환경변수, 로그, 프로세스, 네트워크를 모름 | 새 환경에서 재배포하고 장애 원인을 로그로 찾아 복구함 |
| 금융 도메인 연결 | CRUD 이름만 주문으로 바꿈 | 주문 상태 전이, 금액·수량 제약, 멱등성, 정합성을 테스트로 표현함 |
| AI 학습 소유권 | 답을 읽으면 이해한 느낌은 있지만 재작성·변형이 안 됨 | AI 답을 닫고 재구현하며 오류를 찾아 설명·수정함 |

현재 기준선은 Java·Spring Boot·SQL·AWS 실습을 시작하는 단계다. 반복 질문이 쌓이기 전에는 특정 영역을 확정 약점으로 단정하지 않는다. 질문 로그에서 같은 원인이 두 번 이상 나타나면 `반복 약점 후보`, 재시험에서도 실패하면 `우선 보완 약점`으로 올린다.

## 학습 산출물과 금융 프로젝트 연결

책 예제는 그대로 포트폴리오 대표 프로젝트로 사용하지 않는다. 각 학습 단위를 다음과 같이 변환한다.

`책의 개념 → 최소 독립 예제 → 테스트와 설명 → 금융 주문 도메인의 작은 규칙 → 미래 주문 시스템 구현`

예를 들면 다음처럼 연결한다.

- Java enum·상태: 주문의 `CREATED → ACCEPTED → PARTIALLY_FILLED → FILLED/CANCELLED` 전이
- 예외와 validation: 0 이하 수량·가격, 잔액 부족, 허용되지 않은 상태 전이 거부
- Spring MVC: 주문 생성·조회 API의 요청 검증과 오류 응답
- JPA·트랜잭션: 주문과 체결 기록의 원자성, rollback 확인
- 테스트: 동일 요청 재전송, 부분 체결, 동시 주문의 실패 조건
- AWS: 환경설정 분리, 배포, 로그 확인, 재시작과 장애 복구 절차

## 완료 기준

다음 조건을 충족하기 전까지 이 트랙을 “기초 완료”로 표시하지 않는다.

- 핵심 개념을 책 문장 없이 자기 말로 설명한다.
- AI가 만든 답을 보지 않고 최소 예제를 다시 작성한다.
- 정상·실패·경계 조건 테스트를 직접 추가한다.
- 오류 하나 이상을 로그 또는 디버깅으로 원인까지 추적한다.
- 같은 개념을 금융 주문 규칙 하나에 적용하되, 단순 이름 변경이 아닌 제약과 불변식을 표현한다.
- 코드, 테스트, 회고에서 본인 판단과 AI 도움을 분리한다.

## 답변 운영 계약

앞으로 관련 질문에는 우선 필요한 답만 제공한다. 사용자가 해당 질문이나 공부 내용을 **명시적으로 기록해 달라고 요청한 경우에만** Wiki 학습 기록을 생성하거나 갱신한다. 간단한 오류 해결, 일회성 사용법, 짧은 확인 질문은 자동으로 저장하거나 약점으로 분류하지 않는다.

기록 요청이 있을 때 Codex는 다음을 함께 정리한다.

- 이전 질문과 연결되는 반복 약점
- 지금 질문이 속한 기초 영역
- 최소한의 개념 설명과 작은 예제
- 사용자가 직접 답하거나 구현할 재시험 한 가지
- 미래 금융 주문 시스템과의 실제 연결점
- 이해한 것, 아직 검증하지 않은 것, 다음 기록 항목의 구분

질문 하나만으로 성향이나 실력을 과도하게 일반화하지 않는다. 사용자가 기록을 요청한 내용 안에서도 약점은 관찰 횟수와 재시험 결과를 근거로 갱신한다.

> [!note] Bias Check
> Counter-argument: 모든 학습 질문을 포트폴리오와 연결하면 기초 탐구가 조급해지고 책 진도가 기록 작업에 눌릴 수 있다.
> Data gap: 아직 두 책의 실제 질문·코드·테스트 로그가 없어 약점 순위와 적절한 병렬 학습 속도는 확인되지 않았다.

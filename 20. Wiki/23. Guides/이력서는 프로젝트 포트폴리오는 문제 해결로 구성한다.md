# 이력서는 프로젝트 포트폴리오는 문제 해결로 구성한다

## 현재 편집 기준

> [!note] 최신 사용자 선택
> 2026-10-11 추가 정정: 이력서도 영상의 **첫 번째 문제 해결 중심 형식**으로 작성한다. 개인 1개·팀 1개에서 각각 대표 문제를 선택하고 `문제 원인→해결 과정→검증→결과`로 보여준다. 신입의 기본 구현·본인 역할은 해결/검증 안에서 확인한다. 아래 프로젝트형 약 7줄 틀은 이전 대안이며 현재 형식을 강제하지 않는다. 포트폴리오는 표지·보조 정보 없이 5장, 노션 A3·크기 83이 사용자 설정이다. 실제 PDF 페이지 수는 별도로 검증한다.

최신 편집 원고: [[금융 백엔드 이력서 2장 원고]].

2026-10-11 사용자가 명시한 ideal 문서 작성 기준이다. 영상 전체 자막은 확보하지 못했으므로 영상 발표자의 정확한 발언으로 단정하지 않는다.

| 항목 | 이력서 | 포트폴리오 |
|---|---|---|
| 목표 분량 | 2장 | 5장 |
| 구성 단위 | 프로젝트 나열 | 역량을 가장 잘 보여주는 문제 해결 경험 나열 |
| 설명 길이 | 항목마다 1~2줄, 프로젝트마다 약 7줄 | 선택한 사례의 문제·원인·판단·해결·검증·결과 설명 |
| 연결 | 대표 경험을 짧게 요약하고 상세 사례 링크 | 어느 프로젝트에서 나온 사례인지 표시하고 근거 연결 |

사용자 원문의 `7중`은 맥락상 `7줄`로 해석했다. 약 7줄은 편집 목표이며 이미지 속 모든 예시 항목을 반드시 포함하라는 뜻으로 확대하지 않는다. 실제 줄 수와 페이지 수는 최종 레이아웃에서 확인한다.

## 이력서 프로젝트 블록 예시

후속 영상 인제스트로 [[2026-10-11-YouTube-취준 이력서 10분만에 방향성 제대로 알려줌]] 5:55에서 **프로젝트당 6~8줄**, [[2026-10-11-YouTube-역대 취업난 신입 개발자로 취업해볼까 1]] 1:00에서 약 7줄 조언을 확인했다. 이는 사용자 약 7줄 기준을 뒷받침하는 참고이며 실제 레이아웃의 줄 수와 같다고 보장하지 않는다. 전체 수집 지도는 [[ideal 이력서와 포트폴리오 참고 영상 활용 지도]]를 따른다. 원래 Shorts의 전체 자막 미확보 상태는 그대로다.

아래는 기입 틀이며 아직 수행하지 않은 경험을 작성하는 문안이 아니다. 각 항목은 1~2줄로, 전체는 약 7줄로 압축한다.

1. `[회사/교육/개인] 프로젝트명 · 실제 기간 · 저장소/시연 링크`
2. `서비스: 사용자·업무·핵심 기능 한 문장`
3. `참여: 팀 인원·역할·본인이 맡은 범위`
4. `기술: 실제 사용 기술 · 트래픽/인프라 기준(가정 또는 실측 표시)`
5. `대표 문제 → 본인 해결·판단 → 검증된 결과 → 도메인 의미`
6. `추가 핵심 기여 → 결과(근거가 있는 경우만)`
7. `운영·협업 기여 또는 대표 포트폴리오 사례 링크`

기술 나열과 단순 구현 설명보다 본인 판단과 검증 결과를 우선한다. 가정 TPS·서버 사양을 실제 운영 규모로 바꾸지 않는다. AI 기여와 본인이 설명·수정·검증한 범위를 유지한다.

## 포트폴리오 사례 선정과 연결

[[2026-10-11-YouTube-취준생 대부분 포트폴리오를 잘못 만들고 있습니다]] 0:36~1:38·6:21~7:41은 약 4개의 **제목→그림→문제→해결→결과** 블록과 일관된 순서를 권한다. 사용자 목표 5장 안에 편집할 참고 구조이며 4사례를 고정하거나 미완료 사례를 채워 넣지 않는다. [[포트폴리오 문제 해결 블록과 그림을 편집하는 법]]과 [[이력서 문장은 문제 해결 결과 도메인으로 압축한다]]를 참조한다.

각 프로젝트에서 지원 직무 역량이 가장 잘 드러나는 문제 해결 경험을 우선 고른다. 사례 수는 5장 안에서 결정하며 프로젝트마다 모든 기능을 상세히 설명하지 않는다.

사례는 `사례 제목·출처 프로젝트 → 문제와 영향 → 원인·대안·선택 이유 → 본인 해결 → 검증 조건·결과·한계` 순서로 작성한다. 구조도·실패 재현·전후 측정은 해당 판단을 설명할 때 넣고, 원본 로그·SQL·PR·대표 글은 링크로 연결한다.

현재 금융 원장의 동시성·중복 요청·기관 응답 유실·대사/복구는 사례 후보다. 실제 구현·검증 상태를 확인한 후 가장 강한 경험을 선택한다. 협업 주제와 사례는 미정으로 유지한다.

## 기존 ideal 문서에 적용

- [[금융 백엔드 포트폴리오 2쪽 원고]]는 이전 2쪽 압축 초안이다. 새 분량 기준으로 만들 5장 포트폴리오의 재료로 활용한다.
- [[2026-10-01-Q-ideal-portfolio-submission-draft]]와 [[2026-09-28-Q-ideal-financial-backend-portfolio]]는 프로젝트·사례 재료이며, 이력서는 그 재료를 프로젝트 단위로 압축한다.
- [[거래 원장 실험과 대표 기술 글 계획]]은 개발·학습 길잡이로 유지하고, 완성된 대표 글은 포트폴리오 사례에서 연결한다.

2026-10-06의 포트폴리오 2쪽 기준은 이전 편집 결정이다. 현재 기준은 **이력서 2장 + 포트폴리오 5장**이다. 이번 작업은 참고자료 인제스트이며 실제 이력서·5장 제출본 제작과 PDF 페이지 검증은 아직 수행하지 않았다.

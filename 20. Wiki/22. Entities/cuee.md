# cuee

## Overview

`cuee`는 코레일톡에서 예매나 표 확인에 실패하는 사용자가 다음에 눌러야 할 곳만 보고 직접 누를 수 있게 돕는 접근성 오버레이 앱이다. 사용자를 대신해 예매하는 앱이 아니라, 복잡한 화면에서 선택지를 줄여 사용자가 직접 거래를 이어가게 돕는 방향이다.

전신은 `배우담`이다. 첫 `모두의 창업` 지원을 시작할 때는 노인에게 듀오링고처럼 앱 사용법을 학습시키는 `배우담`이었으나, 지원 준비 중 김규태가 `실제로 노인이 이 학습형 제품을 사용할 것인가?`라고 다시 질문하며 실제 사용 순간에 다음 행동을 안내하는 `cuee`로 방향을 바꿨다. 실제 노인을 관찰하거나 인터뷰한 결과는 아니며, 사용자의 어머니가 이런 기능이 필요하다고 말한 것이 최초 문제 신호였다. `cuee`는 사용자가 현재 화면에서 다음에 눌러야 할 버튼을 마스킹/안내로 보여주는 접근성 오버레이 앱이다. 팀은 CUEE 방향으로 심사를 받았으나 첫 `모두의 창업`에서 탈락했다.

## Product Signal

- GitHub 기준 Kotlin 중심 Android 프로젝트다.
- `배우담`에서 `cuee`로 전환한 핵심 판단은 "사용법을 학습시키는 것"보다 "실제 앱 사용 순간의 마찰을 바로 줄이는 것"이 더 적합하다는 점이다.
- 이 판단의 출발점은 어머니의 문제 제안이며, 실제 노인 인터뷰·관찰로 검증된 결과는 아니다.
- 사용자 제공 맥락 기준으로 김규태는 팀장으로 참여해 초기 콘셉트, 앱의 핵심 역할, 주 타깃 사용자와 마스킹 기술 전략을 제안·결정했다. 실제 코드는 AI가 작성했으므로 Android·Kotlin 기능을 직접 구현했다고 표현하지 않는다.
- 팀 규모는 5명이며, 디자이너 2명, 기획 2명, 김규태 1명(개발자/팀장)으로 구성된다.
- 이번 모두의 창업 2차 지원에서 초기 목표 고객은 코레일톡 설치·회원가입·자동 로그인을 마쳤지만 예매 중 다음 행동을 찾지 못해 역 창구를 방문하는 65세 이상 Android 사용자로 좁혔다. 이는 실제 목표 고객에게 확인하기 전 행동 가설이다.
- README의 검증 목표는 완료시간 50% 감소, 도움 요청 횟수 70% 감소, 실패율 30%p 감소다.
- 사용자 자기보고에 따르면 `실제로 노인이 사용할 것인가?`라는 질문은 첫 `모두의 창업` 지원 과정에서 `배우담`을 `CUEE`로 전환한 계기였다. 탈락 후에는 제품개발계획, 초기 판로와 지속 가능한 매출계획을 구체화하라는 심사의견을 바탕으로 경쟁 서비스 분석과 사업모델을 보완했다. 개인 유료 결제가 이용 확산을 막는다고 판단해 개인에게 무료로 제공하고, 2026-09-14에는 코레일은 모바일 예매 성공과 창구 업무 감소를 검증한 뒤 B2B 이용료·기술 사용료를 협의하며 쿠팡 같은 이커머스는 거래 귀속 후 CPS를 협의하는 두 모델로 구분했다. 모두 계약 전 가설이다.
- 첨부된 `모두의 창업` 최종 심사의견은 자체 기술을 적용한 구현 가능성과 사업 방향은 긍정적으로 평가하면서도, 제품개발계획의 구체성·초기 판로개척·지속 가능한 매출성장 계획의 보완이 필요하다고 명시한다. 탈락 사실과 후속 팀 토론·수익모델 변경은 사용자 자기보고다.
- 팀이 제시한 `이탈률 50% 감소`는 실제 측정 결과가 아니라 기업 제휴를 위해 검증하려는 목표치다.
- 장기 비전은 개인 무료 배포로 시장 가능성을 검증한 뒤 코레일 같은 기업 대상 B2B 접근성 솔루션으로 확장하는 것이다.
- 2026-09-14 사용자 자기보고 기준 Play Store 클로즈 테스트 릴리스는 검토 중이고 확보한 테스터는 0명이다. 승인 후 12명 이상을 14일간 모집할 계획이며, 이 모집군에서 확보 가능한 65세 이상 사용자는 현재 0명이다.
- 사용자는 `cuee`를 아직 0에서 1로 만든 경험이라고 보지 않는다. 현재는 0 to 1 후보 또는 초기 제품화 경험으로 기록한다.
- 사용자는 [[harness]]로 요구사항을 분할하고 AI에 구현 작업을 지시하며 실행·테스트하는 방식으로 `cuee`를 개발했다고 정리했다. 실제 코드는 AI가 작성했으므로 `Kotlin 코드를 모두 독립 작성했다`고 표현하지 않고, 제품 기획·요구사항·개발 workflow 운영·실행 및 테스트를 맡았다고 구분한다.
- 사용자 제공 상장 확인 결과, 김규태를 포함한 5인 팀 `큐`는 경상국립대학교 창업지원단 주최 `2026 경남권 대학생 창업동아리 창업역량강화 심화교육`에서 2026-06-16 대상을 받았다.
- 사용자 제공 상장 확인 결과, 5인 팀 `CUEE`는 `2026 학생창업유망팀 300+ 연계 G-대학생 창업유망팀 동아리 챌린지`에서 2026-08-11 우수상을 받았다.
- 사용자 제공 상장 확인 결과, 5인 팀 `CUEE`는 `2026 GNU 개척리더스 창업 아이디어톤 경진대회`에서 2026-05-27 최우수상을 받았다.
- 사용자는 대상 대회에서 팀 리더·개발 담당으로 주요 아이디어와 콘셉트를 제안하고 발표했다고 보고했다. 이 개인 기여는 상장 자체가 아니라 사용자 자기보고 범위다.
- 2026-08-29 local `main` README에는 JDK 17 빌드, JVM test, APK, accessibility overlay, 음성 명령, fixture E2E, 20초 데모, 결제 전 안전 종료 자료가 문서화되어 있다.
- 재현 가능한 전체 E2E의 상대 앱은 실제 코레일톡이 아니라 같은 package name을 쓰는 `mock-korail` fixture다. 이는 CUEE APK·접근성 서비스·overlay 흐름의 증거이지 실서비스 좌석 조회·예매 성공의 증거가 아니다.
- 사용자 자기보고에 따르면 첫 아이디어톤에서 경쟁 서비스 분석이 부족하다는 질문을 받은 뒤, 경쟁 서비스에 `실시간 실제 상황 보조 / 교육·학습 기반 접근 / 물리적 대면 거래 창구`라는 같은 평가항목을 적용한 비교표를 만들었다. 재첨부 발표자료에서 CUEE만 실시간 실제 상황 보조가 `O`이고, 방문형 1:1 교육 서비스와 케어유는 교육·학습 기반 접근이 `O`, 현장 매표소 창구는 물리적 대면 거래 창구가 `O`인 구성을 확인했다.
- 이 비교를 통해 `학습이나 창구 방문 없이 실제 앱 사용 순간에 다음 행동을 안내한다`는 CUEE의 차별성을 명료화했다. 표는 제품 포지셔닝을 보여주지만 경쟁사에 대한 독립 검증이나 성능 우위를 증명하지는 않는다.
- 프로그램 화면은 U300+ 맞춤형 1:1 멘토링이 팀당 3회임을 확인한다. 사용자는 첫 멘토링일이 2026-06-25라고 보고했으며, 이는 2026-06-16 경남권 대상 이후이므로 대상 수상의 선행 원인으로 쓰지 않는다.
- 사용자는 U300+ 도약과정에서 전국 400팀에 선정되었고, 온라인 전시관 등록과 2026-08-11 오프라인 네트워킹 데이 참여 후 학생창업 페스티벌 최종 40팀 심사에서 탈락했으며 별도 피드백은 받지 못했다고 보고했다. 화면은 온라인 전시관·네트워킹 데이 일정과 최종 40팀 선발 구조를 확인하지만 팀의 실제 참여, 400팀 선정과 탈락 결과는 사용자 자기보고다.
- 김규태는 이 과정을 아이디어의 전국적 경쟁 가능성을 확인하고 창업에 대한 자신감과 도전정신을 얻은 경험으로 해석한다. 2026-09-21 사용자 확인 기준 학생창업 페스티벌 최종 40팀에는 선정되지 않았다.

## Portfolio Use

백엔드 중심 포트폴리오에서는 보조 프로젝트로 둔다. 현재는 Android/Kotlin 구현 경험이 아니라 사용자 문제 정의, 제품 방향 전환, 타깃과 기술 전략 결정, 팀 리딩 경험을 보여준다.

면접 핵심 문장:

> cuee는 노인과 모바일 거래 취약 사용자가 코레일톡에서 다음 행동을 찾지 못하는 문제를 접근성 오버레이로 줄이려 한 앱 프로젝트입니다.

제품 전환 핵심 문장:

> 처음에는 노년층의 앱 학습을 돕는 `배우담`으로 출발했습니다. 어머니가 사용 순간의 직접적인 안내가 필요하다고 말한 것을 계기로 `cuee` 접근성 오버레이 가설로 전환했으며, 실제 노인 사용자 검증은 아직 진행하지 못했습니다.

## Evidence Gaps

- 상장으로 확인되지 않는 개인 기여 범위와 발표자료
- 구현한 Android 기능의 코드/화면 증거
- AI 생성 코드에서 본인이 이해·검증한 범위
- 타깃 사용자 결정과 제품 전환의 관찰·인터뷰·테스트 근거
- 실제 사용자 테스트 결과
- 수익모델 전환 전후 발표자료와 CPS 제휴 구조의 구체적인 수수료율·대상 기업·검증 계획
- U300+ 2·3차 멘토링의 날짜, 회차별 조언과 실제 반영 산출물
- 전국 400팀 선정, 온라인 전시관 등록, 네트워킹 데이 참여를 팀 단위로 확인할 수 있는 제출·참석 자료
- 학생창업 페스티벌 최종 40팀 탈락 결과를 확인할 수 있는 자료
- Play Store 출시 계획과 출시 전 검증 항목
- Android accessibility 권한 심사 통과 가능성과 정책 검토

> [!note] Verification Boundary
> 저장소와 데모 artifact의 존재는 확인했지만 이번 Wiki 검증에서 build/E2E를 다시 실행하지 않았다. 저장소 구현은 AI가 작성했다는 사용자 경계를 유지하며, 사용자의 Kotlin 직접 구현 역량으로 귀속하지 않는다.

# 퀀트 리서치는 가설에서 검증까지 이어지는 과정이다

## Core Idea

퀀트 리서치는 수익률이 좋아 보이는 수식을 고르는 일이 아니라, 시장에서 왜 반복될 수 있는지 설명 가능한 가설을 데이터와 실행 제약 아래 반증하려는 과정이다.

```text
시장 구조·행동 관찰
→ 반증 가능한 가설
→ 시점이 보존된 데이터
→ 신호와 포지션 규칙
→ 비용·체결을 포함한 백테스트
→ 미사용 구간 검증
→ paper/live 결과와 모델 폐기 기준
```

## 좋은 가설을 묻는 질문

| 질문 | 확인할 내용 |
|---|---|
| 메커니즘은 무엇인가? | 행동 편향, 제도, 정보 전달, 유동성 또는 시장 구조 |
| 왜 아직 남아 있는가? | 비용, 용량, 규제, 위험 부담처럼 차익거래를 막는 이유 |
| 어떻게 틀렸다고 판정할까? | 사전에 정한 지표, 기간, 임계값, 대조군 |
| 당시 알 수 있던 데이터인가? | 공시·호가·체결 데이터의 실제 이용 가능 시점 |
| 실행 가능한가? | 수수료, 슬리피지, 시장 충격, 공매도 가능성, 용량 |
| 언제 폐기할까? | 성능 감쇄, 시장 구조 변화, 데이터 품질 저하 기준 |

## 김규태의 학습 연결

이 페이지는 퀀트 직무를 확정한 증거가 아니라 [[김규태 금융 시스템 개발자 취업 로드맵]]의 장기 탐색 지도다. 현재 우선순위인 주문·체결·로그·성능 시스템을 공부하면서, 연구 신호가 실제 주문으로 바뀔 때 생기는 비용과 실패 조건을 함께 살펴본다.

> [!note] Bias Check
> Counter-argument: 사전에 설명 가능한 가설만 고집하면 비선형 모델이 찾는 유용한 패턴을 놓칠 수 있다.
> Data gap: 현재 source는 Gemini 대화 하나뿐이며, 실제 퀀트 연구 절차나 검증 결과가 아니다.

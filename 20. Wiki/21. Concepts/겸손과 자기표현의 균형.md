# 겸손과 자기표현의 균형

## Core Idea

겸손은 자신의 실력과 성과를 숨기거나 칭찬을 부정하는 태도가 아니다. 이 페이지에서 겸손은 **자신 있게 말하되 내가 틀릴 가능성을 열어 두는 지적 태도**로 정의한다.

```text
자기축소 ≠ 겸손
근거 있는 자기표현 + 수정 가능성 인정 = 지적 겸손
```

## Four Distinctions

| 구분 | 건강한 형태 | 피할 형태 |
|---|---|---|
| 자기표현 | 기여와 결과를 근거로 설명 | 과장하거나 타인의 기여 삭제 |
| 피드백 | 반박을 검토하고 필요하면 수정 | 지위·연차로 방어 |
| 칭찬 | 감사히 받고 기여 경계를 밝힘 | 칭찬을 부정해 재확인 요구 |
| 도움 | 자신의 역량과 경계를 유지하며 지원 | 무리한 희생과 원망 |

## Developer And Leader Practice

- 설계 리뷰에서 자신의 안을 명확히 제시하고 반례가 나오면 실험한다.
- 후배나 팀원의 새로운 방식이 더 낫다면 출발 시점과 지위에 관계없이 채택한다.
- 포트폴리오에서는 성과를 숨기지 않되 본인·팀·AI의 기여를 분리한다.
- “제가 틀릴 수 있습니다”로 끝내지 않고 수정할 검증 방법을 제안한다.
- 도움을 주기 전에 일정·역량·책임 범위를 확인한다.

## Reusable Language

```text
제가 맡은 판단과 구현은 여기까지이고, 팀과 AI가 기여한 부분은 이렇습니다.
현재 근거로는 이 선택이 낫다고 보지만, 이 테스트 결과가 다르면 수정하겠습니다.
좋게 봐주셔서 감사합니다. 특히 제가 기여한 부분은 이 문제를 정의하고 검증 기준을 만든 것입니다.
```

> [!note] Bias Check
> Counter-argument: 겸손과 자기표현의 적절한 수준은 문화, 관계, 권력 차이, 상황에 따라 달라진다. 한 대화의 관점을 보편 규칙으로 적용하면 안 된다.
> Data gap: 이 프레임이 김규태의 팀 운영과 피드백 수용에 어떤 효과를 내는지는 실제 사례 기록이 필요하다.

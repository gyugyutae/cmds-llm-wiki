# 메타인지 학습 루프

## Core Idea

메타인지 학습은 “공부를 많이 했다”는 느낌보다 **현재 무엇을 모르고, 왜 틀렸으며, 다음 행동으로 무엇을 바꿀지**를 정확히 보는 학습 방식이다.

```text
진단 → 약점 선택 → 직접 시도 → 즉시 피드백 → 원인 수정 → 간격을 두고 재검증 → 로그
```

루틴의 목적은 의지를 극단적으로 밀어붙이는 것이 아니라, 학습 상태가 보이도록 만들어 다음 행동을 결정하는 것이다.

## Developer Learning Version

| 단계 | 질문 | 남길 증거 |
|---|---|---|
| Diagnose | 정확히 어디서 막혔는가? | 이해 못한 문장, 실패 입력, 에러 |
| Decompose | 개념·설계·구현·디버깅 중 어느 문제인가? | 하위 문제 목록 |
| Attempt | 도움 없이 어디까지 할 수 있는가? | 첫 풀이 또는 최소 구현 |
| Feedback | 예상과 실제 결과가 왜 다른가? | 실행 추적, 테스트 결과 |
| Repair | 어떤 개념·가정·코드를 바꿨는가? | 수정 이유 |
| Retest | 며칠 뒤에도 다시 풀거나 설명할 수 있는가? | 재풀이·회상 결과 |
| Transfer | 프로젝트의 어떤 장면에 쓸 수 있는가? | 적용 후보 |

## AI Usage Boundary

AI는 메타인지를 대신하는 정답지가 아니라 상태를 비추는 도구로 사용한다.

- 정답 대신 다음에 생각할 질문을 요청한다.
- 코드를 고치게 하기 전에 변수와 상태 변화를 추적시킨다.
- 엣지케이스 후보를 만들게 하고 실패 이유는 직접 설명한다.
- AI가 준 힌트와 자신이 바꾼 판단을 분리한다.

## Guardrails

원본 영상에는 높은 공부량과 강한 자기통제를 강조하는 개인 경험이 포함된다. 이를 그대로 보편화하지 않는다.

- 수면과 회복을 희생하지 않는다.
- 계획 미달을 자기비난으로 바꾸지 않는다.
- 시간량보다 오류 수정과 재검증을 우선한다.
- 2~4주 로그를 보고 유지 가능한 루틴으로 조정한다.

> [!note] Bias Check
> Counter-argument: 지나친 자기점검은 학습 불안과 계획 집착을 키울 수 있다. 과제 성격에 따라 탐색과 휴식도 필요하다.
> Data gap: 김규태의 실제 학습 로그가 아직 없으므로 어떤 복습 간격과 AI 사용 경계가 효과적인지 확인해야 한다.

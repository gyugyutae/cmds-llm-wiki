# 취업 스펙은 공고와 프로젝트 증거에 맞춰 배치한다

## 발표자의 관찰과 사용자 적용을 구분한다

[[2026-10-11-YouTube-취업 스펙, 이제 헷갈리지 마세요. 기준 다 정해드리겠습니다. ( 학교 학점 대외활동 수상 )]]는 학점·전공·활동·수상의 가치가 회사 유형에 따라 다르다고 주장한다. 1:07~1:35의 학점 4.0 비교와 2:59~4:06의 기업군별 수상 가치는 발표자의 멘토링 관찰이다. 금융권의 공식 커트라인이나 사용자 탈락 원인으로 사용하지 않는다.

[[2026-10-11-YouTube-합격하는 개발자 포트폴리오 양식 공유]] 10:18~12:06은 강점에 따라 수상·활동·경력 순서를 조정하고 직무와 연결되는 경험을 고르라고 조언한다. 최신순과 강점 우선 중 하나를 절대 규칙으로 고정하지 않는다.

## 문서에 남길 기준

1. 실제 공고의 필수 조건과 지정 입력 항목을 먼저 충족한다.
2. 프로젝트 코드·테스트·직접 판단·협업 결과를 중심 증거로 둔다.
3. 학력·학점·수상·활동·자격은 확인된 명칭·기간·증빙을 사용한다.
4. 활동은 어떤 직무 역량과 본인 기여를 설명하는지 드러나는 것부터 고른다.
5. 미취득 자격·이상형 목표·미수행 구현은 실제 제출본의 완료 경험 목록에 넣지 않는다.

현재 개인 Java 원장과 협업 프로젝트는 각각 직접 구현·검증과 협업·통합을 보여줄 목표 축이다. 영상이 제시한 Kafka·MongoDB·RabbitMQ·JVM·Flutter를 모두 추가하는 스펙 수집표로 바꾸지 않는다. 수상 사실도 구현 능력 또는 실제 사용 효과의 증거를 대신하지 않는다.

[[김규태 금융 시스템 개발자 취업 로드맵]]의 자격·어학 계획과 현재 기여 경계를 유지한다. 이번 작업은 증명서·성적·프로젝트 저장소를 재확인하지 않았다.
